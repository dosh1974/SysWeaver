# core

[⬆ srcWeb](../README.md)

> The UI-less SysWeaver client core (namespace `Sw`): requests, server push messages, cross-window messaging, theme engine, layout state, page protocol, page state, formatting and translation fallbacks. A page (or another project) can use the core alone and still get server messages, InterOp, themes and requests.

| | |
|---|---|
| **Project** | [SysWeaver.HttpServer](../../README.md) |
| **Kind** | Embedded web assets (JavaScript source modules) |

## Purpose

These files are the source modules of the core bundle `sw/core.js` (built by `SwWeb bundle` from `sw/bundles.json`), of the small bundles `sw/session.js` (messaging only), `sw/theme.js` (opt-in theme) and `sw/net.js` (requests), and of the legacy bundle `common/common.js` (core + legacy names + ui + compatibility layer). They are classic scripts (no ES modules), each wrapped in an IIFE with `"use strict"`, and work both concatenated in order (the bundle) and loaded one by one in the same order:

```html
<script defer src="../core/kernel.js"></script>
<script defer src="../core/base.js"></script>
<script defer src="../core/i18n.js"></script>
<!-- ... url, storage, include, format, net, interop, session, layout, session_start, theme, page, activity, draft, access ... -->
<script defer src="../core/init.js"></script>
```

Normal pages load the bundle instead: `<script defer src="../sw/core.js"></script>`. A page that renders its own UI and only needs the SysWeaver messaging loads `sw/session.js` (see [Messaging only](#messaging-only-swsessionjs)).

The bundles share their source files, and no source is copied: every JavaScript bundle is built with `"LoadOnce": true` (SwWeb; `SwWeb bundle` refuses a bundle that shares a source with a load once bundle without being one), so each source runs once per page even when several bundles of the page contain it (`sw/session.js` and later `sw/core.js`: one BroadcastChannel, one session manager; `common/common.js` and `sw/ui.js`: one ui library, one server block overlay). `Sw.Sources` lists the sources that ran and the bundle that ran each (`{"core/session.js": "sw/session.js", "core/page.js": "sw/core.js"}`; only set by the bundles, not when the files are loaded one by one).

Nothing in the core renders visible UI, with one exception: on a page without the app shell, `Sw.Activity` draws a minimal activity line so background work is never silent (in the shell the shell draws the list). Where the old library showed something (server block overlay, loading overlay, error toasts) the core emits events on `Sw.Events` or calls hooks (`Sw.Page.OnLoading`) and the ui library renders.

The core is wire compatible with the old `common/common.js`: old and new windows of the same origin share one session master, exchange InterOp messages and keep the same storage keys.

## Conventions

- Members are PascalCase; functions taking many optional parameters take an options object with PascalCase keys.
- Message types, storage keys and the Web Lock name are fixed by the wire contract (see "Wire contract" below).
- The translation markers may only be written as real calls with a literal first argument (the server rewrites them); never write a marker name directly followed by a parenthesis anywhere else, not even in comments.
- Lines between `//DEBUG_BEGIN` and `//DEBUG_END` are removed by the release build (used in `Sw.Net.Send`: POST is the default in debug builds, unless the web server Params `OptimizedSend` is true: then debug builds use the release GET encodings too; read without a request from the meta `sysweaver-optimized-send` of the templated shell page index.html, in this window or a same origin ancestor, remembered per site in `localStorage["SysWeaver.OptimizedSend"]` for pages opened on their own; false when unknown, as the original).

## API conventions

The rules for new code in the core (the ui library follows the same rules, see [ui API conventions](../ui/README.md#api-conventions)):

- **PascalCase** for every public name: namespaces (`Sw.Net`), functions and members (`Sw.Url.Get`, `Sw.Session.ServerTime()`), state
  properties (`Sw.Theme.Current`, `Sw.Layout.Mobile`) and options keys (`{ Retry, Signal, NoNavigate }`). **camelCase** for locals,
  parameters and private functions inside the module IIFEs. Event names on `Sw.Events` are lower case dotted (`theme.changed`,
  `auth.redirect`); wire message types keep their contract spelling (`Theme.Changed`, `SessionManager.Ping`).
- **Options objects** for optional parameters beyond the essential ones (`Sw.Net.Send(url, arg, opts)`); new APIs don't add boolean
  positional parameters.
- **Subscriptions return an off function** (`Sw.Events.On`, `Sw.InterOp.On`, `Sw.Theme.OnChange`, `Sw.Layout.OnChange`); a loading phase
  returns a remover (`Sw.Page.Loading`).
- **Errors** are thrown (`Sw.Net.Error`) and also emitted as events (`net.error`, `page.error`); helpers in `Sw.Storage` never throw.
- **No UI** in the core: visible reactions are core events or hooks the ui library implements.
- **Legacy names are kept**: every global of the old `common.js` lives in `core/legacy_session.js` (the messaging names, also in `sw/session.js`) or `ui/compat_common.js` and maps onto `Sw.*`; old member names that
  callers used stay as aliases on the new classes (`AbortHandler.raise/addListener/removeListener`); the permanent globals (the theme
  functions `getTheme`, `applyTheme`, `setTheme`, `resetTheme`, `toggleTheme`, `appendTheme` and the translation functions) keep their names
  for ever. A rename is never done in place: a new name is added and the old one stays as a documented alias.

Known inconsistencies, kept because pages and other projects call them (prefer the first form in new code):

| Inconsistency | Prefer |
|---|---|
| `Sw.Util.Clamp` / `Sw.Util.Debounce` / `Sw.Util.Throttle` are also exposed by the ui as `Sw.clamp`, `Sw.Debounce`, `Sw.Throttle`; `Sw.Format.Number` also as `Sw.FormatNumber` | the `Sw.Util` / `Sw.Format` names |
| Two ways to follow a change: `Sw.Theme.OnChange(fn)` and `Sw.Events.On("theme.changed", fn)` (same event) | `OnChange` |
| Boolean positional parameters: `Sw.Session.Subscribe(type, fn, noServer)`, `Sw.Format.Uptime(date, blankIfNeg, invert, now)`, `Sw.Format.DurationMs(ms, blankIfNeg)`, `Sw.Net.IncludeJs(baseUrl, file, noThrow)`, `Sw.Page.Reload(flush, clearHash)` | name the argument in a comment at the call site |
| Result shapes: `Sw.Format.TimeStamp(...)` returns `[tooltip, text]`, `Sw.Format.Value(...)` returns `{ Kind, Text, Title }`; `Sw.Net.IncludeJs` resolves lower case keys `{element, error, errorEv, loaded}` (the old result) | as documented |
| `Sw.InterOp.AddListener` / `RemoveListener` (raw, old style) next to `On` / `Off` (typed) | `On` / `Off` |
| `Sw.Platform.MobileParams()` returns an array `[isMobile, singleColumn, isPortrait, scale]` | `Sw.Layout` state |

### Sw.Cancel (base.js) - one cancellation model (UX guide POP-6, FBK-4, FBK-5)

Dialogs, buttons, the activity list (`Sw.Activity.Run` / `Track` / `Send` / server jobs) and the server's jobs use the same states and words:

| State (`Sw.Cancel.States`) | Meaning | Text (`Sw.Cancel.Texts`) |
|---|---|---|
| `running` | the work runs | |
| `stopping` | Cancel was asked, the work did not return yet (no second Cancel) | `Stopping()` "Stopping…" |
| `cancelled` | **the work confirmed that it stopped**: it threw an AbortError (`Sw.Sleep`, `fetch` with the signal, `Sw.Cancel.Check(signal)`), or the server answered "cancelled" | `Cancelled()` "Cancelled" |
| `done` + `AfterCancel` | Cancel was asked, but the work finished anyway: said so, and nothing is saved / delivered after the Cancel (a file is offered, not saved) | `FinishedAnyway()` "Finished before it could stop" |
| `failed` | it failed | |

"Cancelled" is never shown before the work confirmed it. A cancel that is refused or fails: `CouldNot(why)` "Could not cancel: …", the work runs on (the note stays until the job ends). Helpers: `Sw.Cancel.Settle(promise, signal)` → `{ State, Value, Error, AfterCancel }` (never rejects), `IsAbort(e)`, `Check(signal)` (throw when aborted), `Error()` (an AbortError). `Texts.ReadyNotSaved(name)` "report.csv was ready before it could stop; it was not saved." (the activity list, the table export and restored history use it).

**The model is enforced in code, not only in the docs:**

- **A sent write is never aborted.** `Sw.Cancel.Controller()` makes an AbortController whose signal is marked (`Sw.Cancel.Mark(signal)`); `Sw.Activity.Run` / `Send` use it. `Sw.Net` never aborts a **write** (a `Send` that is not `ReadOnly` / `AbortSafe`) sent with such a signal: a Cancel before it is sent throws an AbortError (nothing was sent), after that the work gets the server's answer, and the job says "Stopping… (what was already sent may still be done)", then "Finished before it could stop" (or `CancelledAfterWrite()` "Stopped; what was sent before the Cancel was done" when the work stopped later). Reads (`Sw.Net.Read`, `Get`, `{ ReadOnly: true }`), `Sw.Sleep` and requests not sent yet stop at once. `Sw.Cancel.Sent(signal)` → `{ Writes, Pending, DoneAfterAbort }`; `Sw.Net.IsWrite(opts, kind)` is the one test of "write" (dialogs and buttons use it for the requests they record).
- **Nothing is delivered after a Cancel.** A job that finished although Cancel was asked rejects its `Finished` (and `await job`) with an AbortError marked `FinishedAnyway` (its `Value` is the work's value; `Sw.Cancel.Settle` reads it as `done` + `AfterCancel`), so the code after the `await` saves / shows nothing and a button never says "done"; the toast / announcement is the job's own `EndText` ("Weekly sales: finished before it could stop", `FinishedAnywayOf(name)`). A rejection marked `SwSaid` (the list said it) is never an unhandled page error.
- **The user's Cancel is state.** A cancel that can't reach the server (the connection is lost) keeps the job "stopping" with `Pending()` "Cancel not sent yet: the connection is lost. It is sent when the server can be reached." and is sent again when the connection is back (a cancel function must be safe to repeat; `CancelJob` is). A server job cancelled on this device is remembered (local storage, 2 h): sent again after a reload, and its history says "… was ready before it could stop; it was not saved." (never "is ready").

```js
// Work that can really stop: check the signal between steps, wait with Sw.Sleep (it throws on abort); a part that was sent is
// never aborted (the server may have it): the job then says "Finished before it could stop" / "Stopped; what was sent before …"
OnClick: () => Sw.Activity.Run({ Title: _T("Publishing {0}", name, "…") }, async signal => {
    for (const part of parts) {
        Sw.Cancel.Check(signal);
        await Sw.Net.Send(api, part, { Signal: signal });
        await Sw.Sleep(500, signal);
    }
}),
```

### Sw.DevOptions (base.js) - option names and types are checked (developer mode)

Every public api checks its options object in developer mode (`Sw.DevMode()`; the walker below lists any that doesn't): an unknown name (a typo, an option of another api: "did you mean …" and the valid options), a value of the wrong type, a value out of range, or an option whose name means something else there (`Read: true` on `Sw.Net.Send`: `Read` is the body reader) is a `[Sw UX]` warning; nothing in production, never a throw. Checked in the core: every api of this README that takes options (`Sw.Net` Send / Get / Live / Read / Message / MessageParts / FailText / IncludeJs / IncludeCss, `Sw.Activity` Start / Track / Run / Send / StartServer / RunServer and `job.Update`, `Sw.Draft` Attach / Remove / `handle.Clear`, `Sw.Page` Loading / Main / Announce / SetDirty / ConfirmLeave / ShowNotAllowed / ShowNotFound, `Sw.Access` Guard / NotAllowed / NotFound, `Sw.Session.WarnTimeOut`, `Sw.Extend.CellFormat`); the ui library, dialogs and tables register theirs. The same helper serves ui, dialogs and tables:

```js
Sw.DevOptions("My.Widget", o, {
    Title: "string", Count: { Type: "number", Min: 0 }, Kind: { Type: "string", Values: ["a", "b"] },
    Read: { Type: "function", Collides: "Read is the body reader; mark a read with ReadOnly: true." },
    Value: "boolean|string", $Check: o => [o.A && o.B ? "A and B collide: pass one." : ""],
});
```

Schema: `{ Name: spec }`, spec = a type (`"string"`, `"number"`, `"boolean"`, `"function"`, `"object"`, `"array"`, `"signal"`, `"element"`, `"promise"`, `"null"`, `"any"`), several (`"boolean|string"` or an array), or `{ Type, Collides, Min, Max, Values, Check(v, o), Hint, Deprecated }`; `$Check(o)` → messages for options that collide with each other. Undefined values are never reported; names starting with `_` are private.

**One registry, enforced by a walker (every public api checks its options, by mechanism, not by list).** Register the schema next to the api under its path name, then check with the name only:

```js
Sw.DevOptions.Register("Sw.Card", { Title: "string", Body: "any", Actions: "array" });   // → the schema
function Card(o) { Sw.DevOptions("Sw.Card", o); … }                                     // looks the schema up
Sw.DevOptions.NoOptions("Sw.Util.RemoveNulls", "o is the value to clean");              // not an options object
```

| Member | Description |
|---|---|
| `Register(where, schema)` → schema | Store the schema of an api (`"Sw.Card"`, `"Sw.Net.Send"`, `"Sw.Form field"`); a later Register replaces it. `Sw.DevOptions(where, o)` without a schema uses it. Normalize aliases (Select `Items` / `Options`) **after** the check. |
| `Schema(where)` → schema \| null, `Names()` → array | The registered schemas. |
| `NoOptions(where, why)` | This api has a parameter that looks like options (`o`, `opts`) but is not an options object (or is internal): the walker lists it as exempt with the reason. |
| `Walk(root = Sw)` → `{ Missing, Checked, Exempt }` | Every public function / class reachable from `Sw` (names starting with an upper-case letter, 3 levels, aliases counted once) whose parameters include an options object (`o`, `opts`, `options`, `opt`, `props`, `cfg`, `config`, `settings`, `params`, or a destructured `{ … }`) and has no registered schema is `Missing` (`{ Name, Params, Aliases }`). |

**Contract test page `core/contracttest.html`** (open it on any app; `?bundle` tests the bundles): calls every documented core function of this README with its documented arguments (an Error, a `Sw.Net.Error` with and without a reason, a text, null for the composers) and asserts the documented return type and behaviour, then runs `Walk()`. No request leaves the page (`core/contractmock.js` replaces `fetch` with an allow-list of mocks: `Api/ct/*`, `serverTime`, static files; anything else is answered 404 locally and listed). Result: `window.SwContractTest = { Done, Passed, Problems, Missing, Blocked }`; a fix of a documented api is not done while `Problems` or `Missing` is not empty. Add a row there for every api you add to this README.

### Sw.Format (format.js)

`Number(v, decimals, thousandSep, decimalSep)` (never exponent notation: `Number(8.6e-7, 8)` = "0.00000086", `Number(1e21)` = "1 000 000 000 000 000 000 000"; a tiny value rounds to zero with the given decimals, as the original), `Amount(currency, amount, options, decSep, thouSep)`, `CurrencyOptions`, `Suffix(v, suffix, emptySuffix, k, decimals, prefixes)`, `Bytes(v, decimals)` ("12.3 kb", "63.4 Gb", the original units), `ByteSpeed(v, decimals)` ("1.2 Mb/s"), `DurationMs(ms, blankIfNeg)`, `TimeSpan(v, zeroText)`, `Uptime(date, blankIfNeg, invert, now)`, `TimeStamp(date, onlyDate, prefix, tab, fmt)` → `[tooltip, text]`, `IsoText(date, onlyDate)`, `LocalToUtc(d)`, `UtcToLocal(d)`, `StringFormat`, `StringFormatArgs`, `CountSuffix`, `RemoveCamelCase`, `KeyValueSplit`, `JoinNonEmpty`, `AddNonNullLine`, `HtmlSafe`, `HtmlAttributeSafe`, `JsonToHtml`, `RankScoreMatch`, `IsValidEmail`, `IsValidPhone`, `IsLetter`, `FileExtension`, `Ext` (Image, Video, Audio, Programming, Compress), `IsImageExt`, `IsVideoExt`, `IsAudioExt`, `IsProgrammingExt`, `IsCompressibleExt`, `IsImageFile`, `IsVideoFile`, `DecimalTypes`, `TypeKinds`, `Value(type, value, format, nextValue)` → `{Kind, Text, Title}` (Default, Number, Boolean, DateTime, Duration, ByteSize, ByteSpeed, Uptime).

**Dates and time zones.** Server time stamps are UTC by convention (the C# exporters use the same rule). `ParseDate(v)`:
an ISO date time with `Z` or an offset is that instant, one **without a zone** (a C# `DateTime` of kind Unspecified) is UTC (not browser
local time), a date-only `"yyyy-MM-dd"` (a C# `DateOnly`) is that calendar day (local midnight, never shifted). `TimeStamp(value, onlyDate,
prefix, tab, fmt)` shows the local time by default, `fmt "utc"` the UTC time, `fmt "local"` the stored fields as they are; a date-only value
is shown as written in every mode, an unparsable value as is. `UtcToLocal` / `LocalToUtc` copy the date and time fields between the local and
the UTC calendar (exact across DST and for :30 / :45 zones; the old offset + `setHours` code lost a day between local midnight and the UTC
offset). `Uptime` and the ui DateTime cells parse with `ParseDate` too. Checked in 11 zones (UTC, Europe/Stockholm, Europe/Lisbon,
America/Los_Angeles, Asia/Kolkata, Pacific/Auckland, Asia/Kathmandu, America/St_Johns, Pacific/Chatham, Pacific/Kiritimati, America/Adak).

**Times: one rule for the whole framework.** One event must read the same everywhere (a log file line, a table cell,
the menu's connection line, the Server page).
1. **Every time in the ui is the viewer's local time** (`TimeStamp`, the ui DateTime cells, charts by default). Its tool tip names the
   zone: "At: 2026-10-20 01:15:19 (WEST, UTC+1)". A time column or field may say it once with `ZoneHint()` ("Times in your time zone
   (WEST, UTC+1)").
2. **A time on another clock is labelled with that clock's zone**, never shown bare: the server's wall clock as "server time 02:15
   (UTC+2)" (`ServerText(d, "hm")` + `OffsetText(ServerZone())`), UTC as "(UTC)" (`TimeStamp(..., "utc")` does it).
3. **"Server time" only labels the server's own clock.** The shell's connection line says "Connected, your time 01:12" while the server's
   zone is unknown, "Connected, server time 01:12" when the server is in the viewer's zone, and "Connected, server time 02:12 (UTC+2)"
   when it differs (the tool tip shows both clocks; the session dialog lists the server time with its zone, your time and the device time).
4. **Server-local text** (a log file, `GetServerInfo.Time`) is converted to local time when the zone is known (`ServerToLocalText`,
   `ServerToDate`), else shown as is and labelled "server time".

The server's zone (`ServerZone()`, minutes east of UTC, undefined while unknown) comes from the `serverTime` endpoint when the server
appends it (`"<ms>;<offset minutes>"`; older servers send only the ms, which still works), or from a page that knows it:
`Sw.Format.SetServerZone(Sw.Format.ServerZoneFrom(info.Time, info.Utc))` (ServerManager's GetServerInfo). It is kept in session storage,
so the shell and every framed page share it.

### Sw.Activity (activity.js) - background work (UX guide FBK-4)

One list of background work per app (a framed page uses the app shell window's list; the shell shows it behind its header button, a sheet on phones). `const job = Sw.Activity.Start({ Key, Title, Text, Progress, Cancel, Retry, EndsWithPage, Kind, Leave })` returns the running job with the same `Key` instead of a second one (`job.IsNew` false). `job.Update({Progress, Text, Title, DoneTitle})`, `job.Done({Text, Url, Open, DoneTitle})`, `job.Fail(error, {Details})`, `job.Cancelled()`, `job.Remove()` (a running job is **cancelled first** and leaves the list when it ended; one without Cancel stays, with a developer warning), `job.State`. **Texts are computed in one place** (the shell's list and toasts, the stand-alone line and the announcements only read them): `job.Title` (running: the title it was started with; ended: `DoneTitle`, ex: the file name of an export, also for restored history), `job.Label` (the title plus the time, ex "report.csv (07:58:12)", when another item has the same title), `job.Text` (the phase line: "Stopping…" / "Cancel not sent yet …" first, then a note that stays such as "Could not cancel: …", then "Waiting for the connection", then the work's own phase: no later `Update({Text})` overwrites a note), `job.EndText` → `{ Text, Kind }` (the result sentence: "Failed: …", "<title>: finished before it could stop" (never "Done" after a Cancel), the result text or "Done: <title>"). `Track(promise, { ...Start options, DoneText, Result(value) })`, **`Run(o, (signal, job) => promise)`** (the safe form: the signal of the cancellation model (`Sw.Cancel.Controller`) is aborted by Cancel, so reads, `Sw.Sleep` and requests not sent yet stop at once, while a write that was sent is never aborted: "Stopping… (what was already sent may still be done)", then "Finished before it could stop"; Done / Fail / Cancelled from the promise; a `Result` that throws fails the job; a running `Key` reused for other work (another Title) is a developer warning: it was not started), `Send({Title, Url, Arg, Download, Retry, Kind})` (a server call run by the shell window: it survives leaving the page; `Url` required; a `Download` (an export, a read) defaults to `Retry: "online"`: it waits for a lost connection, the job says "Waiting for the connection", and goes on; other calls retry only with `Retry`), `Find(key)`, `List()`, `Counts()`, `On(fn)` (a framed page's listener is removed by itself when the page is left: no page leak), `Open()`, `Supported` (offer "Continue in background" only when true), `EndsWith(win)`, `SaveBlob(blob, name)`. **Cancel follows `Sw.Cancel`:** `job.Cancel()` (the list's Cancel; `job.CancelFn` is the same, never the raw function) makes the job "stopping" ("Stopping…", `job.Stopping`, still `Running`); it is "cancelled" only when the work confirmed it (Track / Run / Send: the work threw an AbortError; a server job: the server's answer; a `Start` job: its Cancel function returned, `false` = "Could not cancel"); work that finished anyway is done with `job.AfterCancel` ("Finished before it could stop") and **nothing is saved or delivered after a Cancel** (Track's `Result` is not called, a server file is offered by Open). **`job.Finished`** (every job): resolves with the value when done, rejects with an AbortError when cancelled, with the error when failed, and with an AbortError marked `FinishedAnyway` (its `Value` = the work's value) when the work finished although Cancel was asked (nothing is delivered after a Cancel); all marked `SwSaid` (the list showed them; never an unhandled page error). The jobs of `Track` and `Run` are **thenable** through it, so returning one from a `Sw.Button` `OnClick` keeps the button busy, puts the work in the list, and the button never says "done" for cancelled, failed or finished-after-Cancel work (also in a framed page). **The user's Cancel is state:** a cancel that can't reach the server keeps the job "stopping" ("Cancel not sent yet: the connection is lost. It is sent when the server can be reached.") and is sent again when the connection is back; nothing is saved after it. **A page without the app shell** gets a minimal in-page activity line (bottom start, above the safe area: what runs, the time so far or "Stopping…", Cancel; 44 px items and buttons) and the same result feedback (a toast with Open / Try again, an announcement), so background work is never silent; `Supported` stays false there. **The line never covers the page:** while it is shown the page reserves its height at the end (`html.sw-actline-on`: `body` `padding-block-end`, `scroll-padding-block-end`, the height in `--sw-actline-h`), so the last button can always be scrolled above it; a page with its own fixed layout gives its scroller `padding-block-end: calc(var(--sw-actline-h) + 24px)`; in developer mode a geometry check warns when the line still covers a control (and it is registered with `Sw.Overlay.Register` when the ui library has it). Jobs with `EndsWithPage` (default true; `Send`: false) stop when their page is left; the shell asks first. `Progress` must be a finite fraction 0..1 (anything else, ex a percent `40`, is unknown, with a developer warning "a percent? pass 0.4"). Options are checked in developer mode (`Sw.DevOptions`). `Kind` says what leaving the page means for the job (the leave question uses `job.LeaveText` = `Leave` or `Sw.Page.WorkText(Title, Kind)`: pass `Kind: "server"` for work the server does, `"export"` for exports, `"local"` for work that really stops with the page; without a `Kind` it says "<Title> may not finish.", never "stops"). ### Sw.Draft (draft.js) - drafts of unsent text (UX guide SAF-11)

`const d = Sw.Draft.Attach(textBoxOrField, { Context: "chat." + chatId })` stores the text while typing (500 ms debounce, 64 KB, 7 days; key `SysWeaver.Draft.<site>.<user>.<context>`), restores it into an empty field on the next load with the line "Draft restored (saved 10:42)" + "Discard draft" (Undo toast; one announcement per field, the lines are groups, not live regions, so nothing is read twice), and does not mark the page dirty by default (the original pages never asked "Leave site?"; `Dirty: "restored"` while a restored draft is unsent, `true` for any unsent text). Call `d.Clear()` after send / save. Safe by design:
- **Restored before any input is possible:** in the app shell (which tells the drafts the user, `Sw.Draft.SetUser`) and in a tab where the user was looked up once, the restore is synchronous inside `Attach`. Otherwise nothing is ever saved over the stored draft before it was looked at. **No user request of its own** (P2-A, as the original pages): the shell's user (`Sw.Access.CachedUser` of the top window), else the user this tab remembered (sessionStorage, forgotten on every `user.login` / `user.logout` push); a page opened on its own with nothing stored for the field looks the user up (`GET Api/auth/GetUser`) only at its first save.
- **Never loses text (versioned):** a field only overwrites the stored draft it restored or wrote itself. Any other stored text (typed first on a slow network, a second typed-first in a row, another tab) is **kept** (`<key>~kept`, newest first, 7 days; the old `~prev` is merged in) and offered under the field. The kept drafts are **capped by size, not by count** (`Sw.Draft.MaxKeptBytes`, 256 KB of text per field; `MaxKept` 100 only as a safety): a long text is never dropped because short ones came after it, and when the space is full the oldest go and the line says "1 older draft was removed: there was no more room for drafts." One kept draft: "You have an earlier draft (saved 10:42): "the start of its text…"" with **Restore draft** (a swap: the text in the field becomes an earlier draft, nothing is lost) and **Discard earlier draft** (Undo); several: "You have 5 earlier drafts (the newest saved 10:42). Choose one to restore or discard." with a **picker** of every kept draft (a `Sw.Select`: time + the start of its text, the same look as every select, never wider than the field, 44 px on touch; a styled native select without the ui library) and the same two buttons for the chosen one. A swap keeps every saved time (a restore is not a new save). One announcement per field, also when both lines appear.
- **Cleared when sent, never another tab's text:** `d.Clear()` after a **successful** send / save removes what **this field** wrote; a newer text that another tab typed into the same draft after it is kept as an earlier draft and offered (never erased); the earlier drafts kept for the field stay offered. `d.Clear({ All: true })` (explicit) removes the kept versions too; **`await Sw.Draft.Sent(form)`** does that for every drafted field of a sent form (pass the form, its dialog / card or an element inside it), so nothing is offered again on the sent form, on "Send another" or on the next visit. **A draft is cleared only after its save succeeded:** while a save of the field's form / card / dialog runs (`Sw.Work.Current(field)` of the ui library, ex: `Clear()` called before the request in an `OnClick`), the removal waits for that outcome and happens only on success; a failed or stopped save keeps the draft (`Clear()` returns at once, so work that awaits it never waits for itself).
- **Locked fields:** a field that is disabled, read only, `aria-disabled` / `aria-readonly`, inert or in a disabled fieldset (ex: a sent form) gets no restore and shows no Restore (a restore would change a locked value); the attributes are watched, and `d.Lock(true | false | null)` lets a control say it (Sw.TextBox).
- **Never stores secrets (language neutral):** what the field *is*: `type` password / hidden / file, `autocomplete` one-time-code / current-password / new-password / webauthn / `cc-*`, a masked text (`-webkit-text-security`), a short numeric code field (`inputmode="numeric"` + `maxlength` 4-8), `data-sw-secret`, `data-sw-nodraft`; what it is *called*: name, id, label, `aria-label`, placeholder, title or `Context` that says key, token, secret, password, PIN, passphrase, credentials, IBAN, card number … in many languages, normalized without diacritics ("Passwort", "Kennwort", "Lösenord", "Contraseña", "mot de passe", "Zugangsschlüssel", "пароль", "密码", "パスワード", "비밀번호"); what the *value* looks like: a PEM block, `sk_live_…`, `ghp_…`, a JWT, a connection string or url with a password (`Password=`, `AccountKey=`, `user:pw@host`), "<secret word>: value" in any listed language, a card number (Luhn), an IBAN (mod 97), a 12-24 word seed phrase, a long high-entropy string (not a GUID). A secret field gets a handle that does nothing and a developer warning; a secret value is not written; `Sw.Draft.Set` refuses both (warning). There is no option to force it.
- **Text fields only:** a textarea, a text input or a `Sw.TextBox`; a contenteditable editor (or any other element) gets `Active: false` and a developer warning (keep a rich editor's text with `Get` / `Set`).
- **Subject deleted:** `Sw.Draft.RemoveFor("fakeEmail.reply." + id + ".")` (synchronous) removes every draft whose context starts with the prefix, for every user on this site, kept ones included; call it where the subject is deleted (`Sw.Danger.Run`'s success path). `await Sw.Draft.List(prefix)` → `[{ Context, Saved, Kept }]` (ex: a "Draft" tag on the mails that have one).
- **Wiring mistakes warn:** a second `Attach` on the same field returns the first handle (warning: ex `Sw.TextBox({ Draft })` plus `Attach(tb.Input)`); two fields with one `Context` warn (the last one typed in would win). `Attach(textBox)` also sets `textBox.DraftH`, and `field.SwDraft` is the handle (a Sw control doesn't count a restore as its own edit).
- **The notice** goes after the field row and its hint (field, hint, notice).
- **Pass the component** (`Sw.TextBox` with `Multiline`, or its `Input`): the notice goes under the field row, full width (`Notice` places it after another element).
- **In a dialog** the draft doesn't mark the page dirty (the dialog's own dirty tracking asks); the dialog's "Discard" clears it, any close stops it (`Sw.Dialog.Of(field).OnClose`; also `Sw.Draft.DiscardIn(container)` / `DisposeIn(container)` and the event `sw-dialog-discard`). A field that leaves the document stops by itself; one pagehide handler serves every draft (no leak per closed dialog).
- `Attach` never returns null: a secret field or a missing `Context` gives a handle that does nothing (`Active` false; a missing context logs a developer warning). `d.Dispose()` stops drafting (the stored draft stays).

```js
const notes = new Sw.TextBox({ Label: _TF("Notes", "…"), Multiline: true });
const draft = Sw.Draft.Attach(notes, { Context: "invoice." + id + ".notes" });
// after the save: await draft.Clear();   (or, for a whole form: await Sw.Draft.Sent(form.E))
```

Developer warnings (`Sw.DevWarn(msg, key)`, core/base.js, once per key: the one channel of every framework warning to page authors, gated by the one switch `Sw.DevMode()`: localStorage `SysWeaver.DevWarn` = `"0"` off (a quiet demo on localhost) / `"1"` on (also on a production host), else `Sw.Debug`, else on for localhost and off elsewhere; a page may replace it, `Sw.DevMode = () => false`): a draft without a context, a progress outside 0..1, `Sw.Ready("Tabel")` (no such library after the load), `Sw.Extend.CellFormat` replacing a built-in format (pass `{ Replace: true }` when intended), a shell page not shown after 15 s. Never drafted: passwords, one-time codes, `current-password` / `new-password`, `data-sw-nodraft`. Low level: `Get`, `Set` (refuses secrets), `Remove(context, { All })`, `RemoveFor(prefix)`, `List(prefix)`, `Key`, `IsSecret(field, context)`, `LooksSecret(text)`, `ClearAll(who)` (called by `Sw.Auth.Logout`: an explicit sign out removes the user's drafts; a time-out keeps them; `who`, the GetUser reply the sign out page already has; never a request: else the user this tab or the shell knows, else the drafts of every user of the site).

### Sw.Access (access.js) - what the user may do, and the shared "not allowed" state

| Member | Description |
|---|---|
| `User(reload)`, `Tokens()` | The signed in user (`Api/auth/GetUser`, null when not signed in), its lower cased tokens; cached 30 s. A page in the app shell (same origin) uses the user the shell got at its load and sends no request of its own (the original pages made none). |
| `SeedUser(u)`, `CachedUser()` | The app shell gives its own GetUser reply (`SeedUser`; the shell reloads on every sign in / out); `CachedUser()` returns it (or a fresh cached user) without a request, null when there is none: what `User()` of a framed page uses. |
| `Check(auth, tokens)` | The server rule for an auth text (`ApiInfo.Auth`, `WebApiAuth`): null = open, `""` = any signed in user, `"-"` = no one, else at least one of the comma separated tokens. |
| `Can(what)` | Promise true / false for an ApiInfo (`{Auth}`), an auth text or a token list. |
| `ApiInfo(url)`, `CanCall(url)` | The auth of a server method for the signed in user (`Api/auth/CanCall`: `{Uri, Auth, Allowed}`, the urls asked in the same task go in one request, cached 60 s; older servers: the api info of `Api/debug/GetApiInfo`, see `LegacyApiInfo`), null when unknown; and whether the user may call it (true / false / null = unknown; the server's `Allowed` when known). |
| `HasApiInfo()` | Promise true when the server has `Api/auth/CanCall`. Older servers: true / false: asks once when nothing asked yet (one `GetApiInfo` request, shared with `ApiInfo` callers), so it is never a guess; false once the server refused `GetApiInfo` for this user (403, sign in redirect, 401, 404); null when it can't tell (ex: no connection). See "Dependency on GetApiInfo" below. |
| `RoleText(auth)`, `Requires(auth)` | "Admin or Ops" (Debug left out unless alone); "Requires Admin" (unknown: "Your role doesn't allow this"). |
| `IsDenied(e)` | A refused request: `Sw.Net.Error` with `Status` 403 (or `Denied` true). |
| `Guard(target, {Url, Auth, Hide})` | Disable (or hide) a `Sw.Button` / element the user may not use, tool tip "Requires Admin". Requirement from `Auth` or the api info of `Url`; when unknown the target is disabled after the first `access.denied` of that url (any url without `Url`). |
| `Disable(target, text, hide)`, `ActionDenied(e, target)`, `IsRoleDenied(e)` | Disable now with a reason (class `sw-denied-action`); a refused action (`Sw.Button` does this for a 403 rejection of `OnClick`). **Two signals, never guessed from the text:** a ROLE refusal (`IsRoleDenied`: the server's `X-Sw-Denied: role` header → `e.RoleDenied`; from an older server a 403 without a reason) = a toast with the server's sentence (else "You don't have permission to do this." + the role needed) and the target **disabled** with it as the reason (INP-12), whatever reason text came with it; a 403 with a reason and no role signal is about this request (ex: "only your own domain"): the reason is shown, the target stays usable. |
| `Denied({Url, Error})` | Emits `Sw.Events` `"access.denied"`. |
| `NotAllowed(opts)` | Creates the state element `div.sw-denied` (role alert: lock icon, "You don't have access to this page", "You are signed in as dev.", "This page requires the role Admin or Ops ..." or "Your role doesn't give access to it.", "Ask an administrator ...", a "Go to Home" link: the shell's top window when embedded). No "Try again": a refusal is not transient. It sends no request (the original sent nothing more): the user line comes from the user the page or the shell already has (left out when unknown), the role from `Auth` or a cached `CanCall` answer (else "Your role ..."). A part of a working page (`Scope: "section"`, the default with `Element`) says "You don't have access to this part of the page" / "It requires the role ..." and has no Home link; `Name` names what is refused ("You don't have access to Users"). |
| `NotFound(opts)` | Creates the "not found" state `div.sw-denied.sw-notfound` (role status: search icon, "Not found" / "Services was not found", 'The server has nothing at the address "Api/x/MissingTable" ...', an optional `Hint`, `Links` `[{Text, Url, Icon}]` (default for a page: "Go to Home"); `Title` / `Text` replace the heading / first line). No "Try again": a missing page or table is not transient. |

`Sw.Page.ShowNotAllowed(opts)` (also in access.js): shows that state. `opts`: a reason text, or `{Url, Auth, Reason, Error, Name, Scope, Element}`; without `Element` it replaces the page (the body's children are hidden, so no page action can be used), with `Element` it replaces that element's content. A page scope state with a `Name` also names the page (`Sw.Page.SetName`: the document title and the shell title, ex: "Services" instead of "Table"). It emits `access.denied` and signals "loaded" if the page did not yet; the state is announced once (role alert, no second live region copy). `Sw.Page.ShowNotFound(opts)` shows the not found state the same way (`{Url, Name, Title, Text, Hint, Links, Scope, Element}`; no event); explore/table.js uses it for an unknown table url (404), with the `q` rule and "Show all data tables". Used automatically by `Sw.Page.Main` (a 403 thrown by the main function), `Sw.Table` (explore/table.js), charts (chart/chart.js), the text viewer (edit/text.js, log file), explore logo/icons pages. Styles: `ui/components.css` (`.sw-denied*`).

**Dependency on GetApiInfo (older servers).** Servers with `Api/auth/CanCall` answer the role and the permission of any asked url for the current session, `GetApiInfo` (now Dev and Debug only) is then not used by `Sw.Access` (only by the api inspector page). On an older server the first CanCall request gets a 404 (one per page) and `Sw.Access` falls back to `Api/debug/GetApiInfo`: If a server locks it down (protected, Debug only, or no type service), `Sw.Access` degrades without errors: the first refusal (403, a sign in redirect, 401 or 404) is the only request of the page (concurrent callers wait for it), it is remembered for that user in the browser session (sessionStorage `SysWeaver.Access.NoApiInfo`), `ApiInfo` / `CanCall` return null, `Guard` leaves its target usable and disables it after the first refused request of its url ("Your role doesn't allow this"), and the not-allowed state says "Your role doesn't give access to it." instead of naming the role. A page never breaks; it only loses the role names and the "disabled before the first click". Servers with `Api/auth/CanCall` don't have these limits.

Example:
```js
//  Hide an action the role can't use (requirement read from the api info)
Sw.Access.Guard(deleteButton, { Url: "../Api/logFile/DeleteLogFile" });
//  A page that loads its data itself
try { data = await Sw.Net.Send("../Api/x/Get", null); }
catch (e) { if (Sw.Access.IsDenied(e)) return Sw.Page.ShowNotAllowed({ Error: e }); throw e; }
```

### Sw.Init (init.js) and the start up

The start up of the old `SysWeaverInit` is split in three parts that run once when their file is evaluated (each is part of every bundle that needs it):
- **core/session_start.js** (messaging): url flags `colorscheme`, `ignoreuserchanges`, plus `mobile`, `transparent`, `fillscreen` (Sw.Layout) and `top=true` (this frame acts as a top window: `Sw.Session.IsTop` / `Sw.Page.IsTop`, own session manager); the requested theme (`usetheme`, `settheme`, the InterOp messages `Theme.Changed` (all windows: any other window's `setTheme` / `resetTheme` drops a forced theme, as the original), `color.scheme`, `theme.set`, `theme.use` (frames started with the matching flag)); `Sw.Layout.Init`; the session (`data-sw-no-session` on html: no session, no `serverTime`, no `GetMessages` long poll, no master election, for a page that had no core in the original); the fallback server block overlay.
- **core/theme.js** (theme): `css` (only a stylesheet of this site, `Sw.Url.SafeSameOrigin`; others are ignored with a warning), `Sw.Theme.Apply`, `WatchOs`, re-apply on `theme.request`.
- **core/init.js** (`Sw.Init`, the full core only): `noloader` (Sw.Page.Loading), the page state on a browser reload, interaction and scroll tracking, and the app script: every page that does not load `app/app.js` itself (framed content pages, pages opened on their own) loads it after its deferred scripts, **only when the shell found it has content** (the resource timing of the shell's own load, remembered per site in `localStorage["SysWeaver.AppScript"]`; the server's empty app.js is never requested by other pages, as the original; P2-A) (`Sw.Page.AppScript`, awaited by `Sw.Page.Main`; a body `onload` runs after it), so custom cell formats, edit plug-ins, line icons and themes registered there reach every page; opt out with `data-sw-no-app` on html. Shell only code in `app/app.js` goes in `window.AppMain` or behind `Sw.Page.IsTop`. Extensions of a library that not every page loads go through `Sw.Ready` / `Sw.Extend` (base.js), so app.js never throws on pages without it.

## Messaging only: sw/session.js

Many SysWeaver projects render their own UI (a WebGL editor, a console, a kiosk page) but need the SysWeaver messaging: the server events (sign in / out, reload, pause, file changes, their own push messages), the session keep-alive, InterOp and the server time. Every page of the old library got them from `SessionManager.Create(); SysWeaverInit();` in `common/common.js`; the small bundle `sw/session.js` gives exactly that, with **no theming, no UI library and no framework css**:

```html
<!-- messaging only -->
<script defer src="../sw/session.js"></script>
<!-- messaging + the SysWeaver theme (opt-in) -->
<script defer src="../sw/session.js"></script>
<script defer src="../sw/theme.js"></script>
```

|---|---|
| Session | `serverTime?<tz>;<lang>`, then `GetMessages` `{Cc: 0}`, `{Cc: n}` (the same requests in the same order as the original), master election across tabs and frames (also with old common.js and sw/core.js tabs of the site), handover, server time, the default reactions (reload on `user.login`, `user.logout`, `reload`, `refresh`, a new server instance, unless `SysWeaverIgnoreUserChanges()`; `filereload`), the fallback server block overlay on `server.pause` / `restart` / `shutdown` and a lost connection (`server.error`, "Server communication lost.", as the original), input blocked |

| InterOp | `Sw.InterOp` / `InterOp`, `Sw.Frame` / `PostTop`, `PostParent`, `PostAll` (to this origin, see _docs/WebMessaging.md) |
| Automatic classes | `SwMobile` / `SwDesktop`, `SwPortrait` / `SwLandscape`, `SwNarrow` / `SwWide`, `SwSelf*`, `Transparent`, `FillScreen`, `SwNested` on html and body (`SwNested`: framed by a page of this site that is not the shell, the page padding is 0; not when the iframe has `data-sw-page-padding`), the body events, `Sw.Layout` / `window.Mobile`, `Portrait` ... |

## Opt-in theme: sw/theme.js

`sw/theme.js` (core/theme.js, about 54 KB raw, 14 KB gzip) is the theme engine of `sw/core.js` for a `sw/session.js` page, before or after `sw/session.js` (run first, as a classic script before a deferred `sw/session.js` or with `async`, it queues its start in `Sw.AfterSession` and starts with the messaging core, AS6-3). It applies the theme (`data-theme`, `data-sw-scheme`, `data-density`, the derived variables, the brand stylesheet), follows the requested theme (`?useTheme`, `theme.use`, another window's `setTheme`), `?setTheme`, the OS scheme and the `css` url flag, and defines the theme globals `getTheme`, `applyTheme`, `setTheme`, `resetTheme`, `toggleTheme`, `appendTheme`. A page that loads no `sw/session.js` / `sw/core.js` gets a console error when it has loaded, and no theme. Without `common/theme.css` (a page with its own look) `data-sw-scheme` / `IsDark` come from the built in theme's own scheme (light = light; dark, pro, hacker, application = dark; S6-D5).

## Requests without the full core: sw/net.js

`sw/net.js` (kernel, base, i18n, url, storage, include, net) adds `Sw.Net` (Send, Get, errors, connection state), `Sw.Util` and `Sw.Cancel` to a `sw/session.js` page, without session start, theme or page code (a page that loads only `sw/net.js` gets requests, no messaging). `auth/Auth.js` needs it: a page with its own UI that signs in (EffectWeaver's editor) loads `sw/session.js` + `sw/net.js` + `auth/Auth.js`.

## Bundles and load once

| File | Sources | When |
|---|---|---|
| `sw/session.js` | kernel, i18n, url, storage, include, interop, session, layout, session_start, legacy_session | A page with its own UI that needs the messaging |
| `sw/theme.js` | theme | With `sw/session.js` (either order), for the SysWeaver theme |
| `sw/net.js` | kernel, base, i18n, url, storage, include, net | After `sw/session.js`, for `Sw.Net` requests (`auth/Auth.js`) |
| `sw/core.js` | all core files (the three above without legacy_session, and format, page, activity, draft, access, init) | Every new format page (with `sw/ui.js`) |
| `common/common.js` | `sw/core.js` + legacy_session + the ui library + ui/compat_common.js | Old format pages (theming ON, as before) |

All of them, and `sw/ui.js`, `sw/shell.js`, `app/application.js`, `sw/compat.js`, are built with `"LoadOnce": true` (AS6-1: `sw/ui.js`, `sw/shell.js` and `app/application.js` were not, so an old page with `common/common.js` + `sw/ui.js` ran the ui library twice: two server block overlays, a stack overflow in the focus trap): a source runs once per page, so loading `sw/core.js` after `sw/session.js`, or `sw/ui.js` next to `common/common.js`, is harmless, and `Sw.Sources` tells which bundle ran each source. `SwWeb bundle` refuses a bundle that shares a source with a load once bundle without being one, and `SwWeb check` reports such a page (rule `bundle-overlap`: an error when a bundle of the pair is not load once, a warning when `common/common.js` already contains the other one). They are never needed together: `sw/core.js` contains `sw/session.js` (without its legacy names), `sw/theme.js` and `sw/net.js`; `common/common.js` contains `sw/core.js` and `sw/ui.js`.


## Wire contract (kept identical to the old library)

- BroadcastChannel `SysWeaver`, envelope `{Type, From, MagicXyz: "SysWeaver", To?}`; `From` = sender id or `"Server"`.
- Session: `SessionManager.Ping`, `.Pong {To}`, `.MasterClosed {Cc, ServerEvents}`, `.AddEvents {Events}`, `.RemoveEvents {Events}`, `.TimeOffset {O, Z?, To?}` (Z: the server UTC offset in minutes, so every tab knows the server zone with its first offset), `.GetTimeOffset`, `.GetEvents`, `.OwnedEvents {To, Events}` (new), `.TimeOffset` may carry `Si` (server instance); Web Locks `SysWeaver.SessionManager` (around the election) and `SysWeaver.SessionManager.Master` (held by the master: exactly one master); client generated `server.error` / `server.restore`.
- Server: `Api/application/GetMessages` `{Cc, MessageTypes}` → `{Cc, Prefix, Messages}` or null; `serverTime[?tz;lang]`.
- Theme: `Theme.Changed`, `color.scheme`, `theme.set`, `theme.use`.
- Frames: `PageLoaded`, `LoaderRemoved`, `IframeNavigating {Url, Id}` (answered by the shell with `IframeNavigationHandled {Id, Url, Handled}`), InterOp `WindowLoaded`.
- Storage: `localStorage["SysWeaver.Theme"]`, `localStorage["SysWeaver.ThemeDefs"]` and `["SysWeaver.ThemeAuto"]` (per site root), `localStorage["SysWeaver.Mobile"]`, `localStorage["SysWeaver.Debug"]` (client only, `Sw.Debug`), `sessionStorage["SysWeaver.ServerInstance"]`, page state keys `ScrollX`, `ScrollY`.
