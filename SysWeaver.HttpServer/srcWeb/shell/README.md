# shell

[⬆ srcWeb](../README.md)

> The SysWeaver application shell (namespace `Sw.Shell`): the root page `index.html` with header, main menu and the content frame that hosts every other page, plus the legacy compatibility layer of the old `app/application.js`.

## Purpose

These files are the sources of two bundles (built by `SwWeb bundle` from [`../sw/bundles.json`](../sw/bundles.json)):

| Bundle | Files | Used by |
|---|---|---|
| `sw/shell.js`, `sw/shell.css` | `menu.js`, `content.js`, `shell.js`; `shell.css` | the root page [`../index.html`](../index.html) (new format) |
| `app/application.js`, `app/application.css` (LEGACY) | the same + `compat_application.js`; `shell.css` + `compat_application.css` | old format pages, other projects and srcData templates that load `../app/application.js` after `../common/common.js` |

The shell needs the core (`sw/core.js`) and the ui library (`sw/ui.js`). Nothing runs at load time except defining `Sw.Shell` (and the global `appMain`), so the legacy bundle is safe to load in any page.

```html
<!-- index.html (template, copied to debug.html by the build) -->
<script defer src="sw/core.js"></script>
<script defer src="sw/ui.js"></script>
<script defer src="sw/shell.js"></script>
<script defer src="app/app.js"></script>          <!-- served empty unless an application supplies it -->
<link rel="stylesheet" href="common/theme.css">
<link rel="stylesheet" href="sw/ui.css">
<link rel="stylesheet" href="sw/shell.css">
<link rel="stylesheet" href="app/app.css">       <!-- served empty unless an application supplies it -->
<body onload="appMain()">
```

## Behavior

### Start (`appMain(params)`)

1. **Nested shell guard:** inside a frame of a same-origin SysWeaver shell (ex: a sign in page in the content frame navigated to the site root) the top window is reloaded instead (`top.ReloadAll(true, true)`: hash cleared).
2. The loading overlay (`Sw.Page.Loading`) shows until the menus are loaded and the optional hook `window.AppMain()` (typically defined by `app/app.js`) finished.
3. `Sw.Shell.App.Create(params)` builds the shell. `params` is a `Sw.Shell.Params` (the old `AppParams`), or `window.SysWeaverAppParams` when `appMain` is called without one.
4. The initial page opens: the deep link in the hash, else the first main menu item (the server registers `app/Welcome.html` for anonymous users and `app/Home.html` for signed in users at the top).

Globals set in the shell window: `SysWeaverApp` (the `App`), `SysWeaverAppTitle` (the original document title), `SysWeaverDoneFirst`, `ReloadAll(flushCache, clearHash)` (when not defined by the legacy `common.js`; pages call `top.ReloadAll` to reload the shell, ex: `AuthStartPage` after signing in).

### Layout

```
<body class="sw-shell sw-root [SwPinned | SwCollapsed] [sw-shell-drawer] [sw-shell-overlay]">
  <a.sw-shell-skip>          "Skip to content" link (first tab stop, visible while focused)
  <app-header role=banner>   [menu][back]   <app-ContentTitle>   [user][settings]
  <app-menu role=navigation> the brand bar at the top (a.sw-shell-brand: a link to the start page, the site root `Sw.Url.Root`, named "<app> - start page": the 9:2 app banner span.sw-shell-brandlogo, --sw-brand-banner = ../banner.svg, in the full menu and the phone drawer; the square icon span.sw-shell-brandmark, --sw-brand-small = ../icon.svg, in the rail, placed exactly on the banner's icon and crossfaded with it, see "Brand bar" below), the menu tools (div.sw-shell-mtools: pin, collapse all, expand all), the menu filter box (div.sw-shell-filter), the main menu tree (Sw.Shell.MenuTree)
  <app-content role=main>    the content iframe(s)
  <app-capture>              backdrop while the menu is shown over the content
```

The custom element names are kept from the old shell, so application style sheets (`app/app.css`) keep working.

| State | Wide screens (> 600 px) | Narrow screens (<= 600 px) |
|---|---|---|
| `SwPinned` | menu always shown, content offset by the menu width | (never: the pinned choice is kept for wide screens) |
| `SwCollapsed` | a rail of icons (click an icon to open its page), content offset by the rail | menu hidden |
| neither (temporary) | menu over the content with a faint backdrop; moving the mouse away hides it | a drawer with a dark backdrop |

* **Menu button:** unpins a pinned menu, else shows / hides the temporary menu (`aria-expanded`).
* **Menu tools** (`div.sw-shell-mtools`, a row of icon buttons above the menu filter box; `role=group` "Menu tools"; each button has a short accessible name, a tool tip / long press hint, Tab, Enter / Space, 36 px, the 44 px touch size on touch screens): **Pin** at the left, **Collapse all** and **Expand all** at the right (every folder, `MenuTree.SetAllExpanded`, stored like a user toggle, announced to screen readers). Per mode: the expanded menu (pinned or shown over the page) shows all three; the icon rail only the pin (centered above the search button, a click pins the menu open); the phone drawer and the landscape phone menu only the folder tools (phones have no pin); a menu without folders has no folder tools; nothing to show: no row. **Without the pin** (the drawer, touch screens: `sw-shell-toolsinbar` on `app-menu`) the folder tools sit at the right end of the brand bar, right of the banner (one menu row more; the banner is at most as wide as the bar leaves beside them, the rail's icon box follows it), so the rail has no blank tools row and no row moves. (The pin was in the header before.)
* **Pin button** (the first menu tool; desktops; a pin icon, filled while pinned, tool tip "Pin the menu: keep it open next to the page"; always shown on desktops, signed in or not, whatever the menu size): a toggle (`aria-pressed`, name "Keep the menu open"), stored in `localStorage["SysWeaver.Pinned"]` (JSON bool, per site, not per user: it survives reloads and signing in / out). Without a stored choice the menu starts unpinned (the icon rail), like the original shell, unless `Params.MainMenuPinned` is set or the window is at least `Params.AutoPinWidth` css px wide (default 0 = never); a stored choice always wins. Phones always start unpinned and have no pin button.
* **Mouse:** moving to the left edge (8 px) of the rail shows the menu (not again within 250 ms after it hid); moving over the backdrop hides it. Leaving the window hides it too, except out of the left edge (the border of a window that is not maximized, or a fast move past the edge zone): that shows the menu and keeps it shown.
* **Touch:** tap the backdrop or swipe the menu to the left to close it.
* **On screen keyboard** (`Sw.Layout.Keyboard`, core/keyboard.js): the shell adds `interactive-widget=resizes-content` to the page's viewport tag (Android: the window gets lower, the page and a text field at its bottom stay above the keyboard). While the keyboard is open the top bar steps aside (the page gets the whole low window, the bar is back when it closes), the page and the menu end above the keyboard where the browser only shrinks the visible area (iOS: `--sw-kb-inset`), and the drawer / sidebar choice stays (a tablet in landscape stays a tablet).
* **Keyboard:** the header buttons, then the menu (one tab stop), then the page. In the menu: Up / Down, Home / End, Right (expand / first child), Left (collapse / parent), Enter / Space (activate; a folder without an action toggles), `*` (expand all siblings), letters (type ahead). Escape in the menu (tree or empty filter box) clears an active filter (focus back in the box), else hides a temporary menu and moves the focus into the page; Escape elsewhere closes a temporary menu and returns to the menu button. A page chosen from a temporary menu (or with Enter in the filter box) gets the focus once shown.
* **F6 / Shift+F6:** cycle the focus between the header (first button), the menu (a hidden drawer opens), the page (a temporary menu hides) and, while one is shown, the toasts (the newest toast of the shell or of the framed page, `Sw.Toast.Region()` / `Focus()`; UX guide FBK-8); also from inside same origin pages. Inside an open modal dialog (of the shell or the framed page) F6 belongs to the dialog (between the dialog and its toasts); the page region never gets the focus on its body: the shell returns to the element the user was in (`ContentHost.TrackFocus`), else the top dialog's first field, else the page's main content (FOC-1).
* **`?` keyboard help:** outside text inputs, a dialog lists the shell short cuts (Alt+M, F6, skip link, tree keys, filter keys, Escape). A page's own `?` (ex: the table help, `Sw.Keys` prevents the default) wins; the tree's type ahead ignores `?`.
* **Accessible names:** header buttons have short names ("Show the menu" / "Hide the menu" / "Collapse the menu", "Back", "User menu, <name>", "Settings"), the menu tools too ("Keep the menu open" with `aria-pressed`, "Collapse all", "Expand all"); tool tips may say more. The content frame's `title` is the shown page's title.
* **Skip link:** the first tab stop, "Skip to content" (shown while focused) moves the focus into the page.
* **Menu filter** (`Params.MenuFilter`, default on): a search box above the tree. Typing filters the items by name (parents of matches and the children of matching folders stay; folders open while filtering, the stored state is kept; a "No matching menu items" note shows, the count is announced). ArrowDown moves to the first matching page in the tree (not a folder; ArrowUp on the first item returns), Enter opens the first matching page, Escape clears the text; while filtering folders are never collapsed (Enter / click / Left only expand or move to the parent), so the matches stay visible (an empty box lets Escape close a temporary menu). The rail shows only a search button that expands the menu and focuses the box. The filter is cleared when the menu collapses to the rail / drawer. Type ahead in the tree is unchanged.
* **Hot key Alt+M** (documented in the box's place holder and tool tip only on devices with a keyboard, `Sw.Shell.HasKeyboard()`: not the mobile layout and not touch only; always in `aria-keyshortcuts`): focuses the menu filter (showing a collapsed menu first), also while the focus is inside a same origin page in the content frame (a capture key listener is added to each revealed page window).
* **Rail:** every item has its name as `aria-label`; on phones / tablets (`SwMobile`, ex: a phone in landscape) the rail is a bit wider and shows each name as a short caption below its icon (up to two lines, wrapped only between words: the row text is `span.sw-shell-word` spans; a too long word ends with an ellipsis, the tool tip has the full name); in the rail the row tool tip starts with the name, a long press (touch) shows it as a hint, and keyboard focus shows it in a hint next to the icon.
* **Collapsed folders by default:** the top level folders named in `Params.CollapsedMenus` (default `[]`: every folder starts expanded, like the original shell) start collapsed until the user expands them (stored as `"0"`).
* **Back button** (phones, or `Params.Navigation: true`): `history.back()`, shown only when the previous history entry is this shell document (Navigation API; fallback: a count of the shell's own entries), so it never leaves the application (hidden on the first page). It never goes back across a sign in / sign out: `App.MarkUser` keeps the user of the tab in `sessionStorage["SysWeaver.ShellUser"]`; when a reloaded shell has another user, the current history entry key becomes the boundary (`sessionStorage["SysWeaver.ShellBackFrom"]`).
* **Scroll cue:** while the tree is cut off its edges fade (`.sw-shell-menuscroll.sw-more-above` / `.sw-more-below`, a css mask) and a chevron button under it ("More menu items", `button.sw-shell-menumore`, a click scrolls down by most of a view; not a Tab stop, keyboard users move in the tree) shows that there is more, in the sidebar, the icon rail and the drawer. Kept up to date on scroll, resize and folder changes (`App.CreateMenuMore`).
* **Landscape phone drawer (`max-height: 499.98px`):** compact: the brand bar is 44 px (the folder tools in it, as in every drawer), rows are 36 px (at most; still above the 24 px target minimum), the filter box 36 px and the connection line 32 px. 844x390 shows 7 items (was 4).
* **Connection line (the time rule in core/README "Times"):** "Connected, your time 01:12" while the server's zone is unknown; "Connected, server time 01:12" when the server is in the viewer's zone; "Connected, server time 02:12 (UTC+2)" when it differs. The tool tip shows both clocks with their zones, the session dialog lists the server time with its zone, your time and the device time (with zones). `App.UpdateMenuStatus()` refreshes it.
* **Page title follows the page:** when the shown title is the page's own document title (not a menu item name), the shell watches the page's `<title>` and updates the breadcrumb, the document title and the frame's name when it changes (a record page that sets its title after loading; `Sw.PageHeader` with `MenuTitle: false` sets `document.title` from `Title` / `SetTitle`). `App.WatchPageTitle`.
* **Current item in view:** after a page is shown and when the menu becomes or stops being a drawer (not between the rail and the full menu: there every row keeps its place), `App.ShowSelected()` scrolls the menu (tree, rail, drawer) so the current page's item is fully visible when it is not, aligned to the top of a row (the first visible item is never cut); re-checked 400 ms later (late icons / fonts); a visible item never moves the menu.
* **Temporary menu:** any page change (menu, link inside a page, back / forward, hash change) closes a shown temporary menu in every mode (portrait drawer, landscape phone / desktop menu over the rail), so it never covers the next page.
* **Selection:** the selected menu item is the best match of the shown url (`MenuTree.FindBest`: the exact url, else an item of the same page whose query parameters all match), or none; a focus left on the previous page's item moves to the new one (or is dropped). Only exact menu pages count as recent pages.
* **Recent pages / quick links:** every shown main menu page (not the start page, not a re-show of the same page) is counted in `localStorage["SysWeaver.RecentPages"]`; `App.GetQuickLinks({MaxRecent, MaxLast, MaxTop, MinCount})` (MinCount: Recent only lists pages opened at least that often, default 1) returns `{Recent, Last, Top}` links `{Name, Title, Icon, Url, Open(ev)}` (most used pages still in the menu, the same pages by last visit, the top level pages) for `app/Home.html`.
* **Title:** while a page loads, the menu item name of its url (hidden for urls without an item); when shown, the menu item name of the shown page, else the page's `document.title`, else its path, shown as written (never upper cased: titles can be case sensitive paths); a click copies it (the copy toast quotes the full title). The title text is the shell document's `h1` (`h1.sw-shell-title`, styled as header text). On narrow screens (`SwNarrow`) a long title wraps to two lines (then an ellipsis; the tool tip and a tap show the full title). The document title becomes `"<app title> - <page title>"`.
* **User button:** the user image (`auth/UserImages/Current/small`, refreshed on the InterOp message `UserImageChanged`; shown as the server serves it: the uploaded picture or the server generated one) when signed in ("Logged in as ..." tool tip), else a user icon; click, Enter / Space, long press or right click open the server `User` menu (a single root folder is unwrapped).
* **Icons (Design v2, PORTING.md B15):** the shell chrome (top bar buttons: menu, back, theme, settings; menu tools; the settings menu items full screen and open in new tab; the plus / minus of folders without an icon) uses the line set (`Sw.Icon`); server menu icons are masks in `--sw-text-3` (hover `--sw-text-2`, the accent on the current item) in the sidebar, the rail and the shell's popup menus: a full colour icon url (`...svg*`) is shown as the mask of the same image (`MonoIcon`) and the colour logo class `IconLogo` (ex: the Application theme item) as a mask too; the colourful variants are for content only (Home tiles, tables). App css that styled the old header icon classes (`.IconSettings`, `.IconNavBack` inside `app-SettingsButton` / `app-BackButton`) must target `.sw-shell-hicon`.
* **Settings button:** full screen toggle, the server `Theme` menu as a section (the stored theme is checked; picking a theme closes the menu; a theme item whose icon an earlier theme item already uses gets a distinct one from `Sw.Shell.ThemeIcons`, ex: Pro; the app themes registered with a `Title` (`Sw.Theme.Custom()`, ex: from `app/app.js`) are added to that section, see `_docs/WebBranding.md`), the `User` menu too when there is no user button, the **Density** section and **Text size** (80, 100, 110, 125, 150 %: `Sw.Theme.TextSize`, a section of its own on touch screens and phones, else a submenu at the end of the Density section, since Ctrl + mouse wheel zooms on desktops; `Params.SettingsTextSize`), the **Language** section when the service translates its texts (`Api/application/GetSelectableLanguages` returns the languages, null without a translator; asked once, when the settings button is first pointed at, focused or pressed, so a page load sends no extra request; a press waits up to 1.5 s for it): the current language as a submenu row with every language as a radio item ("Français (French)"); picking one calls `Api/application/SetLanguage` (the session and the signed in user's language), the server pushes a refresh to the pages of the session / user, the page reloads translated (also after 2.5 s without the push); `Params.SettingsLanguage`), "Open in new tab" (the shown page, with the forced theme) and the items added by `Params.OnSettingsMenuOpenFn(menu, close)`.

* **Phones in portrait (< 480 px):** the theme toggle leaves the top bar (the settings menu has the theme section) and the page title wraps to two lines at 15/16 of the size before an ellipsis, so "Process information" or "Recent log entries" are never cut.
* **Menu icons, one per page:** `DistinctIcons(items)` / `MenuIcons` (menu.js): when two pages of one menu show the same svg (compared by the svg file, also between a class and an url), a framework page with a known distinct icon gets it (Problems: warning, Log file, Session cache entries, the three folder sync tables, Data table references, ...); `MenuTree.IconOf` holds the replacements. In the rail the icons use `--sw-text-2` (`--sw-text` on hover).
* **One outline icon style:** server menu icons of the IconModule are drawn as their line twins (`Sw.LineIcon`, ui/README "Icon classes")
  in the sidebar, the rail, the drawer and the top bar menus; only icons without a twin (an app's own) stay masks.
* **Count badges:** `MenuTree.SetBadge(entry, count, text, kind)` puts a right aligned count on a row (a dot in the rail; the item's
  accessible name gets the text). The shell sets the Problems badge itself (`WatchProblems`): the number of parts that failed in the
  last 24 hours (`Api/debug/ProblemsTable`, the Home tile's count), every minute while visible, only when the user may read the table. While the menu is a drawer or hidden the header menu button shows it as a dot and in its name (`MenuAlert`, `UpdateMenuAlert()`; ex: "Show the menu, Problems: 1 part failing in the last 24 hours").
* **Sign out reloads the whole shell (as before the rewrite):** a sign out in this tab (the user menu's *Sign out* opens `auth/Logout.html` in the frame), in another tab, or the server's `user.logout` push (an administrator ended the session, it expired) reloads every shell of the site at once: core/session.js blanks the page right away (nothing of the user, no menu, stays on screen, not even while the browser loads the page again) and reloads it after 100 ms with the hash cleared (`Sw.Page.Reload(true, true)`; the history entry of the sign out page is replaced, so Back never opens `Logout.html` again and signs out a second time). The sign out tells every window itself (`Sw.Session.SignedOut()` from auth/Auth.js `Logout`, InterOp `SysWeaver.SignedOut`); the push does the same, maybe later. The shell has no sign out handler (no dialog over the old page).
* **"You are signed out", once:** the tab that signed out notes it (`Sw.Session.NoteSignedOut`, sessionStorage `SysWeaver.SignedOut`); the reloaded shell takes the note (`Sw.Session.TakeSignedOut()`: read and removed, ignored when older than 20 s) and shows the toast "You are signed out." that closes by itself after 30 s (`SignedOutCloseMs`, `App.ShowSignedOutNotice`). One sign out gives one notice, ever: another reload, the other tabs (they reload without a note), the session check and the push never show it again.
* **Session ended elsewhere:** `WatchSession` asks `Api/auth/GetUser` when any page of the site gets a "not signed in" reply (InterOp `SysWeaver.AuthCheck`, posted by Sw.Net). It has no periodic check by default, like the original shell (which only had the server's `user.logout` push): `Params.SessionCheckSeconds` (0) turns one on (also when the page becomes visible). When nobody is signed in any more (a session that ended without a push, ex: after a sleep) the shell reloads the same way (`App.SessionGone`: blanked, hash cleared) and the reloaded shell says "Your session has ended. Sign in again to continue." once; never twice within a minute (sessionStorage `SysWeaver.ShellEndedAt`), so a server that answers differently can't make it reload over and over. Another user signed in: the shell reloads. A framed page that gets "not signed in" never navigates itself to the sign in page (`Sw.Shell.SignIn = { SignedOut }`, read by core/net.js). The watch is also the connection heartbeat (10 s time-out, `Sw.Net.NoteFailure` / `NoteSuccess`), and it tells the drafts the user (`Sw.Draft.SetUser`).
* **Rail (no layout shift, UX guide LAY-9):** every menu row, section and separator sits at the same height in the icon rail as in the
  full menu, also during the width animation: the rail only hides what it doesn't show (`visibility`), the menu
  tools row and the search keep their heights, a section keeps its label row (an open section is a hairline across it, a collapsed one
  shows its chevron, an item that expands it; the rail keeps the folders' expand state), a separator keeps its label line, and a menu
  mode change no longer scrolls the menu (the scroll the user chose stays; only the drawer re-centres the current item). Measured on all
  11 apps: the icon tops are equal in both modes and in every frame of the transition. **Sideways too:** the icons are one column at
  the rail's centre on every level (`.sw-shell-row` padding `rail width / 2 - scroll padding - icon / 2`; a deeper level indents the
  text, `.sw-shell-text` margin, not the icon), and the menu scrollbar is on the right in an always reserved gutter
  (`scrollbar-gutter: stable`; it was on the left and pushed every icon by its width when a folder expanded): pinning, collapsing to the
  rail and expanding or collapsing folders never move an icon sideways (measured: x = 19 px in every state).
* **Connection line clock:** the label is decided once (server time with its zone when the server sends its zone, else "your time")
  and never changes by itself; until it is known (at most 8 s) the line says "Connected".
* **Brand bar (OWN3-Banner):** the full menu (pinned or shown over the page) and the phone drawer show the app banner (`banner.svg`,
  9:2; its width / height is `--sw-brand-banner-ratio`, 4.5, ui/tokens.css: an app with a banner of another shape sets its own), the icon rail the app icon (`icon.svg`). Both boxes are left anchored at the same place: the icon box is the banner's left
  square, `--sw-shell-brand-s` = min(rail width - 1 rem, bar height - 0.75 rem), 40 px on desktops (banner 180 x 40), 32 px in a
  landscape phone drawer; left = (rail width - s) / 2 (8 px), top = (bar height - s) / 2, whole pixels. The server's generated banner
  (`AddAppBanner`) draws the app icon in exactly that square (the same drawing as `icon.svg`, only its tile continues to the right
  instead of rounding the two right corners), so the two overlap pixel for pixel. Expanding / collapsing crossfades them (opacity, the icon added with `mix-blend-mode: plus-lighter` in the isolated bar, so the shared icon stays at full strength in every frame; the
  menu's 240 ms and easing) while the width animates; nothing moves, the narrowing menu cuts the banner from the right. Reduced motion:
  no animation. A banner of the app's own is drawn in a box of `--sw-brand-banner-ratio` (contain, left); if it has no icon in its left square the change is a
  plain crossfade. The banner file is read ahead once the page has loaded and the browser is idle (earlier when the menu is about to expand),
  so the first expand shows it at once (it came in the middle of the animation). The app name is announced once (the brand bar is an image named after the app, with the name as its tool tip); there is no name row under the bar (S7a-B-4: the banner shows the name, the row repeated it).
  Measured on 8201, 8205, 8208 and 8211 (1920 / 1366, 5 themes, the phone drawer): 0 px of icon movement, the icon box pixel identical outside its right corners.
* **Phone titles:** a single word wider than the title box is drawn up to 20 % smaller, else on one line with an ellipsis (`FitTitle`,
  `.sw-shell-title-fit`): it never breaks inside the word.
* **Menu scroll cue:** the "more below" chevron has its own row under the tree; the fade is 1 rem at the bottom, 0.75 rem at the top.
  A drawer opened by a tap or a click shows no focus ring on the focused item until a key is pressed (`sw-shell-pointeropen`).

### Menus (`menu.js`)

The server menu model (`Api/application/GetMenu` with comma separated names `Default`, `User`, `Theme`) is `WebMenu {RootUri, Items}` of `WebMenuItem {Id, Name, Type, Title, IconClass, Data, Children, Flags}`.

| Type | Action |
|---|---|
| 0 Path | folder (expand / collapse) |
| 1 Table | shows `explore/table.html?q=../<Data>` |
| 2 Embedded | shows `<Data>` |
| 3 Link | the whole window navigates to `<Data>` |
| 4 LinkExternal | `<Data>` opens in a new tab |
| 5 Js | `window[Data](item, style, isUserClick)` when `Data` names a global function, else `Data` is evaluated as a statement in the global scope (the server's theme items: `if(setTheme('dark'));false`); a truthy result hides the menu |
| 6 Chart | shows `chart/chart.html?q=../<Data>` |
| (function `Data`) | client built menus: `await Data(item, style, isUserClick)`, a truthy result hides the menu |

Urls are relative to the site root. `Flags`: 1 disabled, 2 checked. `Id "-"`: a separator (with an optional label). `IconClass`: an icon class (`IconTable`) or an icon url (`icons/x.svg`, `../icons/x.svg`, a trailing `*` = full color). A folder without an icon or action shows plus / minus. Collapsed folders are stored as `localStorage["SysWeaver.MenuCollapsed.<menu>.<Id or Name>"] = "1"` (menus `Main`, `AppSettings`, `NoName` ...). Embedding items ignore a click on the already selected item; modifier clicks are ignored.

* `new Sw.Shell.MenuTree({Menu, Name, Context: {Navigate(url, item, ev), Hide(), Style}, Label, Class, OnActivate, DefaultCollapsed(item, level), OnTopUp()})`: `.E` (role tree), `.Entries`, `.UrlMap`, `Activate(entry, ev)` (a user activation of the already selected page item only calls `Context.Hide()`: a temporary menu closes), `Select(entry)`, `SelectUrl(url)`, `FindUrl(url)`, `FindBest(url)`, `Toggle(entry)`, `SetExpanded(entry, bool)`, `Focus()`, `Filter(text)` (-> `{Count, First, FirstLeaf}`; `Toggle` never collapses while filtering), `SetRail(bool)`, `Visible()`. `Style.SelectFn(item)` is called on selection changes.
* `Sw.Shell.RunItem(item, ctx, ev)` runs one action; `Sw.Shell.ShowMenu(anchor, items, ctx, {Sections, Align, Side, ...})` shows server items as a `Sw.Menu` (folders become submenus, or sections with `Sections`).

### Content frame (`content.js`)

* Each navigation creates a new hidden iframe (class `Hidden`, no generic load fade); the previous one is hidden and removed after 25 ms. The forced theme is forwarded (`?useTheme=`).
* The frame is revealed when its page posts `{Type: "LoaderRemoved"}` (`Sw.Page.Loaded`, the old `PageLoaded`) - only messages from the current frame's window count - or 1 s after its load event. On reveal the frame's `<html>` gets `Embedded`, the menu item of the url is selected (also for pages that redirect before they are shown) and the title is set.
* A shown page that navigates by itself (links, `location`, server redirects) is hidden instantly on `pagehide` and the next document is revealed like a new page (no unthemed flash).
* A page taking longer than 300 ms shows a thin loading bar and, fading in shortly after, a centered spinner with "Loading..." (`div.sw-shell-pageloading`, a polite status) until it is revealed.
* History: every navigation pushes `history.state = url`, hash `#` + Base64(url) (the deep link format); the first page replaces the entry of a deep link (so back to it works) and adds nothing otherwise. Back / forward re-show the url without a new entry; the state-less first entry re-opens the first menu item. Navigating clears the page state stored for that url (`Sw.History.ClearOther`).
* Pages navigate the shell with `Sw.Page.Navigate(url, "_self")` (the old `Open`), which posts `{Type: "IframeNavigating", Url, Id}` to the top window and answers it with `{Type: "IframeNavigationHandled", Id, Url, Handled}` (posted back to the content frame when the message has an `Id`; `Handled` true: the shell shows the url, the page cancels its own fallback navigation; false: the url was refused, the page navigates itself at once; a page that gets no answer navigates itself after 100 ms, 1 s inside the shell); the shell only accepts it from the window of its content frame (`event.source === Host.Frame.contentWindow`) and from this origin, so a frame nested in the page, a popup or another tab of this site can't drive the shell by posting messages. This is not an isolation boundary: same-origin script can always reach the content frame (ex: `parent.Sw.Frame.PostTop(...)` from a nested frame posts with the content window as the source). The real guard is `SafeContentUrl`: every accepted url is still limited to http(s) urls of this site or an exact external Embedded menu item.
* Security: deep links (the hash), history states and `IframeNavigating` urls are untrusted. `App.SafeContentUrl(url)` accepts only page urls of this site (`Sw.Url.SafeSameOrigin` and `Sw.Url.IsPageUrl`, or the url of a main menu item: never a raw server method such as `Api/...` or `ServerManager/KillProcess`, which may perform an action on GET) and the exact url of an external `Embedded` item of the main menu; anything else (other sites, `javascript:`, `data:`, `blob:`, ...) is refused: a deep link opens the first menu item, and a toast says "This link can't be opened here". `ContentHost.Navigate` also refuses every non http(s) url (returns false). Defense in depth: a content frame that showed a page of this site and then navigates itself to another origin (a plain link or a script in the page) is never revealed; the shell shows the last page again (`OnForeign`) and tells the user. `LoaderRemoved` from a page of this site only counts from this origin. Every refusal is also announced to screen readers (`Sw.Page.Announce`). `Sw.Page.Navigate` itself opens other sites in a new tab (see core/README.md). Titles: a page title set from the url (`Sw.Page.SetLinkTitle`, ex: explore/table.html `n`, explore/api.html / edit/type.html `q`) is shown as plain text (never html), cut to 80 characters (`App.IsLinkTitle` + `Sw.Page.LinkText`; also the tool tip, the frame name and the document title), without a caption (the owner removed the "Text from the link:" pill: a title is a title).

* **Offline pages (FBK-9, FBK-6):** a page opened while `Sw.Net.Online` is false (no request is sent), a frame whose first document is the browser's network error page, a page still loading when the connection is lost, or one not shown after 15 s while the server can't be reached shows `div.sw-shell-pageerror.sw-shell-pageoffline` ("Could not open <menu name>. The server can't be reached. The page opens by itself when the connection is back", Try now) instead of an endless loader (the header and breadcrumb name the page, "Monitoring > Active sessions"; while it is shown the offline line keeps only its text, so there is one "Try now"), and opens by itself on `net.online` (`ContentHost.ShowOffline`, `OfflineUrl`). A page not shown after 15 s while online gets a developer warning ("call Sw.Page.Loaded()").
* **Missing or failed pages:** a page whose navigation answered 400 or more (Navigation Timing `responseStatus`; or the server's plain text "Not Found" on browsers without it) is not revealed: the content host shows `div.sw-shell-pageerror` with a Design v2 `Sw.EmptyState` instead ("Page not found / This page is not available in <app>. The link may be old, or the page belongs to another app.", Back and Go to Home; 401 / 403 "No access to this page"; 5xx "The page could not be shown" with Try again) and the top bar title says so. Options `AppName()` and `OnHome()` of the `ContentHost` (the shell passes its app title and `OpenFirst`). The next navigation removes it.
* **Dialogs of the page dim the whole app:** `BindFrameModal` / `SetFrameModal`: a `{Type: "SwDialogModal", Count}` message from the content frame (or a frame nested in it) puts `app-modalscrim` over the chrome, raises `app-content` (`body.sw-shell-modal`), makes the other `app-*` elements `inert` and focuses the frame; a scrim tap or Escape in the shell posts `{Type: "SwDialogOutside", Key}` back. Reset on every navigation. See ui/README.md "Dialog rules".

### UX guide support (version 1.0)

* **Leaving a page (SAF-10):** while the shown page is dirty (`Sw.Page.SetDirty` in it or a frame inside it) or runs `Sw.Activity` work with `EndsWithPage`, `App.Navigate` (menu, links, `Sw.Page.Navigate`, `IframeNavigating`) and Back / Forward ask "Leave without saving?" ("Leave" / "Stay", Stay focused; `App.ConfirmLeaveContent`); work alone asks "Leave this page?" with what really happens (`job.LeaveText`: "You won't see the result of Kill devenv (33936) here; the server may still finish it." for `Kind: "server"`, "… stops; the file is not saved." for exports). The open question follows its entries (`ConfirmLeave(texts, { Source: () => App.ContentLeaveTexts() })`): its text updates, and when the work ended and nothing else is lost it closes by itself as Stay. Stay keeps the page and its menu item; Leave clears the page's dirty keys. The tab title starts with "●" while the page has unsaved edits (`ApplyDocTitle`). Running shell jobs make closing the tab ask (`beforeunload`). `Navigate(url, { Force: true })` skips the question.
* **Back closes the top pop-up (MOB-3):** the browser's Back (button, phone gesture, mouse button) first closes the top pop-up of the shell or of the page in the frame (`Sw.Popup.CloseTop("back")` when the ui library has it, else the Escape semantics, so a dirty or busy dialog stays and says why), then the menu drawer, and only then goes back. The Navigation API cancels the traversal when the browser allows it, else the popstate handler undoes it (`history.go`). On the entry page (nothing in-app to go back to) the shell adds one history entry of its own while a pop-up is open (`BindPopupHistory`, state `{SwPopupGuard}`, from `Sw.Popup.OnDepth`), so Back closes the sheet there too instead of leaving the app; the entry is removed again when the pop-up closes another way, and before a menu item reloads the shell (Sign out: `Sw.Page.BeforeReload` → `DropGuardNow`, P3-A-11). Only on phones and touch screens (on a desktop no entry, as the original). The tab title's "●" is reset whenever the content frame is replaced. The scroll position of the previous page comes back on Back (SAF-12, `Sw.Page.TrackScroll`).
* **Activity list (FBK-4):** `<app-ActivityButton>` (`button.sw-shell-activitybtn`, Params `ActivityButton`) left of the theme switch, also on phones (44 px on touch), shown only while this session has activity (a job running, finished or failed and not removed from the list; `UpdateActivityButton`, `app-ActivityButton[hidden]`): with an empty list the top bar has no activity tool, and as the first tool of the right group its appearing never moves the other tools; badge `span.sw-shell-actbadge` only while jobs run or a failure was not opened (a failure: "!" and the danger colour); accessible name "Activity: 1 running, 1 failed". It opens a popover (`.sw-shell-activity-pop`), a sheet in the phone layout, with each job's state in text, progress, Cancel, Open, Details, Try again and Remove. Starts are announced, a failure once as an alert (inside the page's open dialog when there is one); opening the list focuses the list itself (or the job of a toast's Show / Details, `App.ShowActivity(jobId)`), never a job's Cancel, and closes the result toasts it shows (no toast left over the phone sheet); results show a toast, which waits while the tab is hidden (the tab title shows "✓ Export done" until then). A cancelled job shows "Stopping…" until the work (or the server) confirmed it, then "Cancelled", or "Done at … · Finished before it could stop" (its toast "<title>: finished before it could stop", never "Done"); a refused cancel says "Could not cancel: …" in the item only (the Cancel button adds no "not done" toast); a cancel that could not reach the server stays pending ("Cancel not sent yet …") and is sent when the connection is back. Every text comes from the job (`job.Label`, `job.Text`, `job.EndText`): ended exports are titled by their file, items with the same title get their time, and only the newest Open is a primary button. Server jobs restored after a reload, a new session or from another device are listed quietly with the server's end time and "kept until …" (no toast); closing / reloading the tab asks only for work that runs in the tab (server jobs go on). See `Sw.Activity` in core/README.md.
* **Offline line (FBK-9):** `div.sw-shell-offline-line` (Params `OfflineLine`): one calm floating line "Offline, retrying…" (`role="status"`) with "Try now" while `Sw.Net.Online` is false (also reported by framed pages, `SwNetState`), then "Back online" for 4 s (the original's requests decide, S6-Ops-3: the shell's message poll retries every 5 s and its server time sync every 15 s, so "Back online" comes within about 5 s of the server's return; no probe of its own while the shell polls; no probe while another request, ex: a live table's 3 s retry, keeps failing: its next try decides). In the phone layout it takes the place of the page title in the top bar ("Offline" and a 44 px icon button "Try now"), so it never covers the page's controls; the sidebar connection line says "Offline, retrying…" too (one wording). It never moves the page or blocks input itself. After 3 failed message polls (about 10-15 s) the server's blocking overlay "Server communication lost." covers the shell as in the original (`Sw.Session.BlockOnLost`, default true since series 6: owner parity), until the first poll that succeeds; the line stays under it.
* **Time-out warning (ACC-7):** `Sw.Session.WarnTimeOut({At, Extend})` shows "Your session is about to end" (`alertdialog`, opened last so it is above any dialog, also over a dialog of the framed page) with "Stay signed in" (focused; Escape, × and Enter keep the session too) and "Sign out"; the focus returns where it was.
* **Page changes are announced (FOC-6):** the document title becomes "<app> - <page>", a page opened from a temporary menu or the filter box gets the focus (its frame is named by the page title), and a page shown while the focus stays in the chrome (a pinned menu item, Back) is announced by its name (`Sw.Page.Announce`); the first page of the shell is read with the document.

Example (an app page with a form):

```js
form.OnChange = () => Sw.Page.SetDirty("user", form.Changed ? _T("Your changes to {0} are lost.", user.Name, "…") : null);
await save(); Sw.Page.ClearDirty("user");
```
