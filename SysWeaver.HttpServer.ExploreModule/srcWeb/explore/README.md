## Purpose

The pages of the *Debug* menu entries declared on [`ExploreHttpServerModule`](../../ExploreHttpServerModule.cs) (`explore`, `explore/icons.html`, `explore/logo.html`), the API inspector, and the data table component used by `table.html`, by every `[WebMenuTable]` menu item (`explore/table.html?q=../<api>`), by `[TableDataUrl]` cell links and by other pages (ServerManager `keys.html` / `services.html`).

All code is built on the Sw client library of [SysWeaver.HttpServer](../../../SysWeaver.HttpServer/srcWeb/README.md) (`sw/core.js`, `sw/ui.js`, `sw/ui.css`; see `core/README.md` and `ui/README.md` there). The new format pages load:

```html
<script defer src="../sw/core.js"></script>
<script defer src="../sw/ui.js"></script>
<script defer src="page.js"></script>
<link rel="stylesheet" href="../common/theme.css">
<link rel="stylesheet" href="../sw/ui.css">
<link rel="stylesheet" href="page.css">
```

`explore.js` is the exception: the server template [`srcData/index.html`](../../srcData/index.html) (it can't change) loads the legacy bundle `common/common.js` (= Sw core + ui + compatibility layer) and calls the global `Build(data)`. `explore.js` only uses Sw, which works under both bundles. `table.js` works the same way under the new bundles and under the legacy bundle (old format host pages).

## Behavior

### Data table (`table.js`)

- **Layout** (Design v2, PORTING.md B13): `div.sw-table` is the table frame (one bordered panel) with, top to bottom: the tool bar (`div.sw-table-toolbar`: the search field, Filter with a count badge, the log quick filter "Warnings and errors", then at the right the icon tools Sort (cards), Columns (a corner badge counts the hidden columns), Density (hidden on narrow bars), Download, Refresh and the cards / grid switch; one line, the words go on narrow bars, container query), the filter chips (`div.sw-table-chips`, only while filters are active), the rows area (`div.sw-table-area`: the scroll area `div.sw-table-scroll` with the grid `table.sw-table-grid` (sticky header, filter rows, data rows), and over it the skeleton rows while loading (`sw-table-loading` on the root until the first answer), the empty / error / not allowed states (`.sw-table-state`: icon in a sunken circle, title, one sentence, action) and the edge cues), and the footer (`div.sw-table-foot`). The footer is one line with fixed slots: at the left the range ("1-15 of 15" on the last page; "1-25, more follow" while more rows follow, tool tip "More than 25 rows. The total is not counted ...": every request has a look ahead of one row (`LookAheadCount: 1`), so `RowCount` means "at least this many rows"; `aria-rowcount` is -1 while the total is unknown) and the "Changed" legend (`span.sw-table-changed`, after the first live refresh that changed a value; its space is reserved before it shows, so it never pushes anything); at the right edge "Rows" + the page size select (Auto (n), 10, 25, 50, 100) and the icon pager (first, previous, "Page 3", next; fixed squares). The range and page slots only grow (`UpdateFoot` measures them), so paging, live refreshes and the legend never move the pager (0 px, measured every frame). In `table.html` (option `Page`) the frame fills the window and the rows area takes all the free height, so the footer is always at the bottom edge of the frame: with 2 rows, on a short last page (Next / Back stay under the mouse), with no rows, while loading or refreshing. Embedded tables (one rule for every app): a **fill table** (option `Fill`, default when the container has the class `sw-fill` (a `Sw.PageLayout` fill page section) or `sw-table-fill`) takes the free height of its container and its footer is at the bottom of the frame, like a page table; any other embedded table (a table in a card or between other content) is as high as its rows, its footer follows the last row and is sticky at the bottom of the window while the page scrolls. The empty and error states never draw outside the rows area: they shrink and scroll inside it, and on low screens (<= 500 px, landscape phones) they drop the icon circle. The empty state of an unfiltered table says "No rows to show" and "There is nothing in <table name> right now." (the page header title, ie the menu name), or the texts of the options `EmptyTitle` / `EmptyText` (`table.html`: url parameters `et` / `ed`); filtered: "No matching rows" + "Clear search and filters". On narrow bars (< 520 px) the legend, "Page n" and the word "Rows" are left out. `table.html` shows a compact page header (`header.sw-table-ph`: the menu name of the table as h1 and the live refresh line or the log note), hidden on phones (portrait < 600 px wide and landscape <= 500 px high).
- **Calm grid** (Design v2, PORTING.md B13): row hairlines only (option `ColumnLines: true`, class `sw-table-vlines`: subtle column rules); every grid cell paints the opaque background of its row state (`--sw-table-rowbg` = `--sw-table-row` / `-row-alt` (stripes) / `-row-hover` (hover and keyboard focus in the row) / the failing row tint), so pinned columns (`sw-table-pin` / `-pin2` / `-actpin`, the narrow first column) are never see-through and match their row in all themes; they have a 1 px divider (no shadows), the edge cues are 1 px lines plus the arrow button. Headers follow the alignment of their values (`UpdateHeadAlign`: `th.sw-table-thr` right aligned numbers / sizes / dates, the sort icon before the title; `th.sw-table-thc` centred; otherwise the title starts where the values start, the sort icon after it). Links have no underline at rest (on hover / focus only); the external / web search glyph shows only on the link's hover / focus (faint on touch screens; the search glyph is moved after the text, also out of the no-wrap span of the first word, `QuietCell`); the glyph takes no width at rest (a negative end margin), so a link column's text starts at the same x as its header and every other column. Row action icons that are server icon files with a line twin (`Sw.Icons.LineOf`; table.js registers `skull.svg` → `kill`) are drawn as the line glyph, so no filled icon sits among the outline ones; on touch screens the card's actions button is a 44 x 44 target. Row action buttons (Actions format, ex: Kill) are ghost buttons, always visible on every row (UX guide LST-2) in the secondary text colour and in the text colour on the row's hover and keyboard focus (`RowActions: "always"` is the only mode, kept for compatibility); destructive ones (`sw-cell-action-danger`) turn danger on hover; the per row visibility and the confirmation are unchanged. The "Changed" tint is as the original (DataTableFlash): 25 % of the second accent (`--sw-accent2` = `--ThemeAcc2`) mixed into the row colour, fading in 1 s (ease) in every theme, also with reduced motion (a colour change in place, nothing moves; owner report 4 #10), and is only shown when the row still shows the same item (`tr.SwItem`, key columns): rows moved by the sort are not tinted. Zero values are muted by colour (not opacity). The table makes its own elements `border-box`, so it works on pages without `sw-root` (`LockWidths` also converts for a content-box app style). On low screens (<= 500 px high, phones in landscape) the grid is compact whatever the density: 32 px rows without vertical padding, a one line 32 px header (sort icon only on sorted columns), a 32 px tool bar without words and a 32 px footer (844x390: 6 whole rows, was 3). A failed first load shows "Not loaded" in the footer ("Loading..." again on Try again); the page header title is the menu name from the first frame (in the shell `Sw.MenuTitle`; on its own the `MenuName` promise of `table.html`, the title stays hidden until it resolves) and never the api method name; without a menu item: the server title, else `Sw.Page.NameFromUrl`.
- **Grid widths and headers**: header titles are at most two lines (`FitHeadTitles`: a title of several words gets the width of its best two line split, measured with the title font; a 2 line clamp is the safety net, the tool tip has the whole title). Icon only columns (C# `TableDataNoTitleAttribute`, `th` / `td.sw-table-iconcol`) are compact and centred, named by the tool tip, screen reader name and card label; a chart pictograph ("📊") is drawn as a line chart icon in the secondary text colour. Wide frames (`SpreadWidths`, after the first render of a column set / frame width): the natural column widths are measured; when they need less than the frame, the free width goes first to the cut text columns (up to their whole value, at most 40 % of the frame / 48em; the per column cell maximum is raised in the table's own style element), then the rest of a still cut text value, then up to 2.5em to every column, and the rest is an empty filler cell at the row end (`UpdateFill`, `sw-table-filled`, `--sw-table-fill`: a `tr::after` table cell in the row colours), so sparse tables at 2560 px are not spread over 2400 px, while row lines, stripes, hover and the header band still reach the frame edge (the grid never ends mid-frame). A column that grows later takes its width from the filler. A `Text` cap (`TableDataText`, ex: 30 characters) cuts the value at that length, as the original (the click popup and the tool tip have the whole value). Row actions never cover a value and are never hidden (CMP-B1 / B3): the Actions column is a real column, pinned at the right edge (`sw-table-actpin`), with the buttons (`span.sw-table-actbox`, `display: contents`) on every row; when the columns fill or overflow the frame and a row has three or more actions, the column is a quiet row menu button instead (`sw-table-actmenu`, `button.sw-table-rowmenu`, the row's actions with their confirmations, destructive ones last); one or two actions always stay buttons. Keyboard: Tab from a cell goes to its row's action buttons (or the row menu button) and then out of the grid (`SetActive` puts the active row's actions in the tab order); Enter on the actions cell runs its only action; the cell menu (right click, Space, Shift+F10 on any cell) starts with the row's actions (`RowActionItems`). **Self check:** a shown column that is 0 px wide in the grid (its values could not be seen or clicked) is a `[Sw UX]` developer warning after every width update (`UpdateFill`); `table.ZeroCols()` returns those column names (empty = fine), for tests. After a row action request succeeds (the server's outcome, see "Row actions" below; `ActionClick` / `ActionResult` / `ActionDone`), the row is marked at once (`tr.sw-table-acted`, values muted, a "✓ End session: done" note at the row end / in the card heading, with the time in the tool tip). A final action (one that ends or removes the item: End session, Kill, Delete, Withdraw invitation ...) is done once. **The server declares it** (G47, Admin N53): the 8th part "final" of the action format (C# `TableDataActionsFullAttribute` with `TableDataActionFlags.Final`), which Sw.Cells puts on the button as `data-sw-final="true"` / `"false"` (`actionIsFinal`); the words of the text or the tool tip never decide it (a tool tip "…their open sessions end" once made Force password reset final and hid the row's re-read actions). An action without the part (`TableDataActions` / `Ex`, a page's own format) is not final: the rows are reloaded after it, as the original did after every action. A final action: the row is updated in place (`tr.sw-table-actfinal`: its actions are hidden and left out of the menus) and the rows are not reloaded at once, so the row keeps its place until the next live or manual refresh; any other action reloads the rows at once. Time columns (DateTime cells) say their clock in the header tool tip: "Times in your time zone (WEST, UTC+1)" (`Sw.Format.ZoneHint`, core/README "Times"), or "Times in UTC" after "Show UTC times"; a "(UTC)" in the server's column description is left out over local times. File type images of a cell (`../icons/ext/<ext>.svg`, ex: MIME mapping) are the built-in multicolour file type icons, as on the explore pages (`img.sw-table-ftype`, 22 px high; the extension is the accessible name). Downloads are named "<table name> <yyyy-MM-dd HH-mm>" (the viewer's local time); the CSV exporters round floating point columns to the decimals of their `Number` format (C# `CsvTableDataExporter`), the Excel exporter keeps the value and shows it with the column's number format. Range text: "1-100, more follow" while the total is not counted (the server counts only the look ahead row); a RowCount larger than the page plus the look ahead is a total the server counted and is shown as "1-100 of 183". Cards: the column that names the row (`TitleCol`: option `CardTitle`, else a text column named like an identity: Name, Title, User, Login, Email, Subject, Host, File name, Label ..., else a text key column that is not a token / hash / key) is the card title (first line, larger, no label, always on the closed card); a card with row actions has a kebab in its heading (`button.sw-table-cardact`, `CardActions`: the row's actions with their confirmations, and "Show all fields"). Narrow tool bars (below 480 px): Download, Refresh, Density and the cards / grid switch move into a "More tools" menu (`MoreMenu`, `.sw-table-tover` / `.sw-table-morebtn2`), so the search field keeps ~170-220 px on a 390 px phone.
- **Compact screens / cards**: below 600 px, or on a touch / mobile device below 1000 px (phones in landscape; the border box width, with 16 px of hysteresis to leave a layout, so a width never alternates between two layouts, owner report 4 #7), the table is `sw-table-compact` and by default `sw-table-cards`: every row is a card (the row number as heading, then one "label: value" line per visible column; labels are the `data-label` attributes = column titles; every column is shown, empty values are left out: cells marked `sw-table-blank`; all values use the page font and size, numbers with tabular digits; several pills (Tags) or buttons (Actions, Toggle) keep their width and wrap as whole items in the value column), cards are side by side when there is room, nothing scrolls sideways. On low screens (max-height 500 px, phones in landscape) each card takes a full line with its fields in columns (two at 844 px) and scrolling snaps to the card tops, so whole cards are shown; there the Sort / Filter bar moves into the scrolled area: shown above the first card at the start (a scroll snap point), sticky at the top, it slides away while scrolling down and comes back on scrolling up (`UpdateCardBarHide`, `sw-table-barhide`; also on keyboard focus) and long values (`sw-table-long`, over 40 characters) take the full card width. Compact cards: a card with more than 7 values shows its first 6 (the rest are `sw-table-extra`; row action buttons, ex: Kill, are also `sw-table-extra`: only in the opened card, never in the short summary) and a "Show all n fields" ("Show all n fields and actions" when the card has row actions) button at its bottom (`button.sw-table-morebtn` in the row number cell, `aria-expanded`; "Show fewer fields" closes it; open cards are remembered by row number until the rows change by sort / filter / search). The header and filter rows are hidden; a tool bar above the cards (`div.sw-table-cardbar`) has two equal halves: a "Sort" button (shows the sort column; a menu with the sortable columns, ascending / descending and "Clear sort") and a "Filter" button (shows the number of active filters; a dialog with the same filter options as the filter rows: per column operation, value, "Not" and "Match case" toggles, up to 3 filter sets, Reset). "f" and the column menu "Filter" open the dialog in the card layout. Long values (`sw-table-long`) are clamped to 3 lines on cards; the cut ones (`sw-table-clamped`, faded bottom, `aria-expanded`, `UpdateClamps`) show all on a tap (`sw-table-unclamp`, until the value changes; the tap does not copy) or on keyboard focus. The footer button "Table view" switches to the grid (with a sticky row number and first data column; it scrolls sideways), "Card view" back; the choice is remembered per browser in `localStorage["SysWeaver.Table.Layout"]` ("grid" / "cards"). Desktop always uses the grid. A grid wider than its area shows edge cues (`sw-table-edge-l` / `sw-table-edge-r`, `UpdateEdges`): a shadow on the left while columns are scrolled out, a shadow and an arrow button (scrolls right) on the right while more columns follow. Column titles wrap between words (never inside one) so wide tables need less width; the header tool tip starts with the full title. Page tables (`sw-table-page`) keep the footer at the bottom of the frame (the empty state takes the free height under the header). Each row has `data-sw-item` (`ItemText`: the key column values, ex: "Name: msedge, Id: 40544"), used by the confirmation of destructive cell actions. The grid keyboard model is the same in both layouts.
- **Polish (CR10)**: in the wide grid (desktop) the identifying columns are pinned while scrolling sideways (`UpdatePins`, `sw-table-pin` / `sw-table-pin2`, `--sw-table-p2`): the first data column, plus the second when it is the first visible text key column (ex: Process information "Id" + "Name"), so row actions at the far right always show next to the row name (nothing is pinned when that would take more than a third of the width). A last column with the Actions format (row actions, ex: Kill) is pinned at the right edge (`sw-table-actpin`, `ActPinW`; the right edge cue moves left of it), so row actions never need sideways scrolling. A column scrolled under the pinned row actions (or out at the right edge) fades out over 20 px before the edge line (`.sw-table-edge-r::before` to the row colour, `::after` to the header colour over the header band `--sw-table-headh`), so a header or value is never cut through a letter ("Paged syster / memor"). A multi line text value (a call stack, an exception; `sw-table-multiline`) gets a narrow grid column (16em; a click shows it all), so it does not push other columns off screen. Data text uses the normal text color (`--sw-fg`): numbers, dates and names are not drawn in the accent; links show in the text color, the accent underline only on hover / focus. A cryptic one letter column title ("C", "M") shows its explanation (`shortTitleHint`, ex: "Cpu use details") as the header label (`th.sw-table-hinted`, narrow, wraps) and card label. Icon only links (ex: the chart links, `td.sw-table-iconlink`) get the cell tool tip as accessible name and the word "Show" next to a larger icon in the cards. Long words of text cells get soft breaks (`softBreaks`, `<wbr>` after `. / \ _ : , - ? & =` and at camelCase boundaries) so card values wrap at name boundaries ("ServerManager/GetMem / HistoryShortChart"); in single line grid cells the `<wbr>` are hidden. Phones in landscape: the page buttons show their arrows only and the search field keeps 13ch ("Search..." readable); cards use three field columns (long cards: label above value, about 150 px columns) and the "Show all n fields" button sits in the card heading, so two closed cards fit the screen.
- **Requests**: TableDataRequest `{Cc, Row, MaxRowCount, LookAheadCount, Order, Filters, Param, SearchText}` posted to the api (`Sw.Net.Send`, reload when the user caused it). A timed refresh asked while a request runs runs right after it; a user change starts its request at once and the running one finishes with its answer ignored (see Updates). Live refresh after `RefreshRate` ms (<= 0: 5000, min 100) with the last `Cc`; the refresh goes on while the page is hidden or offline, like the original table. Empty / unreadable replies and errors: before any data was shown an inline error state (`div.sw-table-error`: a plain words summary (`ErrorSummary`, written for ops: what failed ("The server could not reach <host>, a service it depends on." for provider failures, naming the host when the technical text has one; else no answer in time, no connection, not found, or "The data could not be loaded.") and where to look ("The server log (Log, or the Log file viewer) has the details of the failure."), never "ask an administrator"), a "Technical details" disclosure (`details.sw-table-error-detail`: the raw error and the table api, selectable, with a Copy button) and the "Try again" button; Refresh, Download, the column chooser and the search field are disabled while it is shown, and in the not allowed / not found states (`SetToolsDisabled`)) replaces the grid; with data on screen the stale data stays and one error toast is shown (repeats merge). Both are removed by the next successful request. A request has no time limit by default, like the original table (a refresh may be a long poll; option `Timeout` in ms aborts it: "The server did not answer within N seconds"). Every failure is retried after 3 s (`RetryDelay`), like the original table: also the error state ("Try again" fetches at once), offline, and the not allowed (403) / not found (404) states, which go away when the table answers again. A reason repeated by server retries ("(No connection ...) (No connection ...)") is shown once. Default sort on the first open (no stored state): option `Order` only; without it no order is sent, like the original table (the server's own order; `Sw.Table.KnownOrders` is kept empty for callers). Search: applied on Enter, leaving the field or Clear (the input's change), like the original table: no request while typing (the same text again refetches; `SearchApply` commits the typed text for `FlushPending`). The export menu first applies a pending search / filter value and waits for its rows (`FlushPending`, `PendingUser`), so its counts ("The 3 rows you see on this page", "The 12 rows that match your filters and search" when the total is known) and the "Current view" file match the screen. Log tables (a visible `SysWeaver.MessageLevels` column) get a "Warnings and errors" footer toggle (`ProblemsB`, `ToggleProblems`, `ProblemsOn`, `UpdateProblems`; `aria-pressed`): it sets the level filter "Greater or equal Warning" in every filter set (the server compares the level order, so Warning and Error pass; shown in the filter row, stored with the state), off clears it; with no match the empty text says how to show every message again. Enum columns sent as numbers with known names (`Sw.Table.EnumNames`: FakeText Status / Failure / Channel (flags), Scheduler task Type) show the translated name, the number in the tool tip, and their filter inputs list the names. Filter inputs of enum columns with known values (`Sw.Table.EnumValues`, ex: `SysWeaver.MessageLevels`: Error, Warning, Info, Debug) offer them in a drop down list (a shared `datalist`). A stored page beyond the end jumps to the first page on the first load. `Cols` may be omitted on later responses; the header / filters are only rebuilt when the columns change.
- **Rendering**: rows and cells are reused; a cell is rendered (`Sw.Cells.Update(td, type, value, flash, format, next, refresh)`) only when its value or format changed; changed values flash (`sw-flash`, the original 1 s fade from 25 % second accent) during live refreshes. Card layout: long cards (14+ columns, ex: Process information) show two fields per line with the label above the value on portrait screens; zero values (`sw-null`) are muted by color so their labels keep the label color. Generic rows (`{Values: []}`) and typed rows (`row[colName]`) are supported. Hidden columns (`Props & Hide`) get no header / filter / cell. `WordWrap` columns wrap. ### Table page (`table.html`)

`tableMain()` reads `q` (the table api url, required; resolved with `Sw.Url.SiteUrl`, the same rule as api.html: a value starting with `./`, `../`, `/` or a scheme is relative to `explore/` like a link (`../Api/debug/ApiTable`, the menu form), any other value is relative to the site root (`Api/debug/ApiTable`); both are the same table), `p` (Param; the old `jp`, javascript run to compute the Param, was removed for security: a link with `jp` shows a message instead of the table, see below), `uniqueParam` (opt-in per-value saved state: folded into the state key, `HashString(url + "\0" + uniqueParam)`, option `KeyParam`; used alone it is also the Param, with `p` it only seeds the key), `n` (title / name: untrusted text, set with `Sw.Page.SetLinkTitle`, at most 80 characters, shown by the app shell as plain text, no caption), `r` (accepted, unused), `s` (state json), `f` (filter json), `et` / `ed` (the empty state title / sentence of the unfiltered table: plain text, at most 120 characters), `header=false` (no page header, ex: an iframe of the page inside a page with its own header), `title=false` (the page header without its title: only the live line, ex: a pop-up window whose title bar shows the name; the document title is still set); in a frame whose iframe has `data-sw-page-padding` (a host without padding around it, ex: a Fenrir pop-up) the page has the theme page padding (`html.sw-table-padded`, `--sw-page-px`); the document title becomes `n` or the server's table Title. Opened on its own (not in the shell or another page's frame: `html.sw-table-alone`) the page has the standard page margin (`--Margin` = `--sw-page-px`, 32 / 24 / 16 px; 4 / 8 px on low screens). api.html shows its `q` the same way until the server knows the API (then "API: <its url>"). The loader is removed after the first response. Without `q` the page explains how to open a table (in-page `div.sw-table-error.sw-table-missing`, no toast).

**Security**:
- `q` must be a http(s) url of this site (relative, or absolute with the same origin). Any other url (another host, `//host/...`, `data:`, `javascript:` ...) shows an in-page error ("the table address must be on this site") and nothing is fetched, so a crafted link can not make the page load and show another site's data.
- **`jp` removed**: the old `jp` parameter was javascript source taken from the url and executed in the page to compute the Param, so a crafted link (`table.html?q=...&jp=...`) ran arbitrary script in the signed-in user's session (reflected XSS). A scan of every project on the development machine that uses SysWeaver (SysWeaver, SysWeaver.Services, EffectWeaver, SysWeaver.Tests, SysWeaver.Temp, SysWeaver.Tools, the managed services) found no producer (all links, `[TableDataUrl]` attributes and C# url builders use `p`), so it was removed rather than restricted. A link with `jp` must not silently show other rows (the original used the Param the script computed), so the page shows "This link uses the removed jp parameter … so the table is not shown …" (in-page `div.sw-table-error.sw-table-jp`, `role="alert"`, plus a console warning) and fetches nothing (S5-A-2). Pass the Param as `p` (url encoded); a computed Param belongs in the code that builds the link.

Options (remembered in `localStorage["SysWeaver.Api.Curl"]`, the method is per page: POST for APIs with an argument, else GET), all on one line (the selects, the segmented control and the switch are `--sw-control-h` tall): GET / POST (`Sw.Segmented`), Result format (the output serializers of the service, `Accept` header; hidden when the service has only one; a binary format or a raw API adds `-o <name>.<ext>`), Compress the argument (None or deflate, deflate only when the service reads it; deflated by the page (`Sw.Util.Deflate`, raw deflate) and sent as the binary GET argument `?_d<base64url>`; disabled, showing None, for POST and APIs without an argument: a compressed body can't be put on one curl command line) and Compressed result (`--compressed`). An uncompressed GET adds `--globoff`. An API that needs a signed in user gets a note about the session cookie. The serializers and compression methods come from `Api/debug/GetApiIoInfo` (TypeService, Dev; built in defaults when it is missing). GET none / deflate and POST were checked against a service.
- **Result card**: before the first call an empty state ("No result yet", the shortcut); during a call the old result is dimmed (`api-busy`, `aria-busy`); then tabs Result + JSON (a read only Ace editor of the result, 3 to 40 lines with its own scroll bars inside the card, and a Copy button) with the status badge (OK, Error / Refused, the mime type) and the time in ms in the tab bar, and the footer "Called 22:28:27" (no user lookup). Result: a read only `Sw.Edit`; a null result shows the empty form of the return type (`edit/GetDefaultInstance`) and "null" in the JSON tab, as the original (P3-A-9); Preview (image / iframe of the blob for raw mime APIs; a click opens it in a new tab); an API that returns nothing shows "Done"; an error shows the error state ("The call failed" / "Not allowed" with the role) and the server text. A change of the argument after a call removes the result ("No result yet" again), like the original page (`MarkStale`).
- Storage: `localStorage["SysWeaver.Api." + q]` (last argument without `$type`), `SysWeaver.Tabs.Api.Args` / `SysWeaver.Tabs.Api.Results` (selected tab index).

### Custom cell formats

A column's format (C# `TableDataColumn.Format`, ex: `[TableDataRawFormat("Stars;5")]`) is `Name;arg1;arg2...`. `Sw.Cells.Update` (ui/cells.js) picks the renderer by the name in `Sw.Cells.FormatFormatters` (built in: Default, Number, Url, Img, Tags, PerRowFormat, ByteSize, ByteSpeed, Toggle, Actions, Duration, Json, Text, MD, Uptime, WebColor), else by the C# type (`Sw.Cells.TypeFormatters`). To add a format:

```js
// app/app.js (app wide) or the page's own script, before the table renders: Sw.Extend.CellFormat waits for Sw.Cells (safe on every page)
Sw.Extend.CellFormat("Stars", (e, value, formats, nextValue, flash, type, onRefresh) => {
    // e: the cell (td or a card value), value: the raw value, formats: the format split at ";" (formats[0] = "Stars")
    if (Sw.Cells.Reset(e, "Stars"))          // true when the cell had another renderer: set the static classes once
        e.classList.add(Sw.Cells.Classes.Center);
    const max = parseInt(formats[1]) || 5;
    const n = Math.max(0, Math.min(max, value | 0));
    const text = value === null || value === undefined ? "" : "★".repeat(n) + "☆".repeat(max - n);
    Sw.Cells.SetText(e, text, n + " of " + max, flash);   // text, tool tip, flash class (live refresh tint)
    return e;
});
```

- `Reset(e, kind)` clears what another renderer left on a reused cell and returns true on a kind change; `SetText(e, text, title, flash)` / `SetNodes(e, signature, buildFn, title, flash)` set the content (only when the text / signature changed, so live refreshes do not flicker).
- The table renders the cell again only when the value or the format changes; the card layout shows the same element with the column title as its label (`data-label`), and Ctrl+C / "Copy value" copy the cell text.
- `Sw.Extend.CellFormat(name, renderer)` = `Sw.Ready("Cells", C => C.FormatFormatters.set(name, renderer))` (core/README.md `Sw.Ready`): it runs at once where the ui library is loaded and as soon as it loads elsewhere, so `app/app.js` never throws on a page without it. A plain `Sw.Cells.FormatFormatters.set(...)` still works in a page script that loads the ui library.
- The renderer must exist before the table's first render in the same window: register it in the page's script, or app wide in `app/app.js` (the core loads it in the shell and in every page that does not load it itself, framed `explore/table.html` included, before `body onload` runs; see core/README `Sw.Page.AppScript`; a page can opt out with `data-sw-no-app`).
- **Unknown format**: a name that is not registered renders the plain value (the Default renderer) and warns once in the console ("Sw.Table: unknown cell format ..."), instead of the type's renderer reading the arguments (a number column with "Stars;5" showed "2.00000").

### Local data (`Rows`) and the row cap

A table can show rows the page already has (an import preview, parsed rows, a computed list) with the same tool bar, filters, search, sort, paging, cards and keyboard, without a table api:

```js
const t = await Sw.Table.Create({
    Element: host, Name: "Import preview",
    Rows: rows,                       // objects (values by column name) or arrays (values in column order)
    Cols: [                           // optional; default: from the first row (property names, type from the JavaScript value)
        { Name: "Id", Type: "System.Int32", Props: 1 | 8 | 32 | 128 },     // Props as Sw.Table.Props (here: sort, filters, key)
        { Name: "Name" },                                                  // Type default System.String, Title = the name in words
        { Name: "Size", Type: "System.Int64", Format: "ByteSize" },
        { Name: "When", Type: "System.DateTime" },                        // Date values are kept as ISO text, as the server sends them
    ],
});
await t.SetRows(newRows);             // replace the rows later (page, sort, search and filters are kept)
await t.SetRows(polled, true);        // a live update: tinted changes, the order is held under the pointer / focus
```

- Sort, filters (the same operations as the server, all must match), search (every typed word in some value, case insensitive) and paging run in the browser; the footer shows the exact total ("1-20 of 1 195"). Columns without `Props` can be sorted and filtered (text filters on text, order filters on numbers and times). Charts are not offered; Download saves the rows of the current search, filters and sort as a CSV file. There is no live refresh (call `SetRows`, with `live: true` for polled data) and no Refresh button (the page owns the rows); the pager says "Page 2 of 5" (the total is known).
- The state (page size, sort, filters) is stored under `"local:" + Name` (else the page path), as for an api table.
- **Row cap:** a page never draws more rows than its page size. An api that ignores `MaxRowCount` (answers 10 000 rows for a page of 20) gets its page cut out of the reply (from the asked row when the reply is the whole list) and one console warning ("Sw.Table ...: the api answered 10000 rows for a page of 20 ..."). Fix such an api to honor `Row` / `MaxRowCount`, or give the rows as local data.

### Lists of rows: use `Sw.Table`, not a hand-made table

Any list of rows a page shows (records, results, a preview, a polled status list) is a `Sw.Table`: with a table api (`Url`) or with the rows the page already has (`Rows`, above). A hand-made `<table>` / `createElement("table")`, or a list of row `div`s with a click listener, gets none of the rules the UX guide asks for, and each page then has to build them again (and usually forgets some):

| You get with `Sw.Table` | A hand-made table has to do it itself |
|---|---|
| Modifier clicks only focus (INP-2), text stays selectable (INP-30), Ctrl+C copies the value (INP-31) | `Sw.ModifierClick(ev)` in every row / cell handler |
| A live update never moves rows under the pointer or the focus (FBK-7: `SetRows(rows, true)`) | Hold the order itself while the pointer is on a row |
| Sort, filters, search with the shared wording (LST-3 / 7), counts and `aria-rowcount` (LST-5), empty / error / not allowed states (FBK-6) | Its own sort, empty text, error state, row counts |
| Cards on phones, the keyboard grid, touch targets, density, row actions with confirmation, busy state and one result (FBK-2 / 4 / 5) | Its own phone layout, keys and busy rows |
| Download as CSV (local rows) or with every exporter (api), in the background with Cancel (FBK-4) | Its own export and progress |
| Offline: the rows stay, "Not updated since …", no error toast (FBK-9) | Its own offline handling |

```js
// a list the page has (ex: parsed rows, a polled list): local rows
const t = await Sw.Table.Create({
    Element: host, Name: "Devices", Rows: rows,
    Cols: [{ Name: "Id", Type: "System.Int32", Props: 1 | 8 | 32 | 128 }, { Name: "Name" }, { Name: "Seen", Type: "System.DateTime" }],
});
setInterval(async () => t.SetRows(await Sw.Net.Get("Api/myapp/Devices"), true), 5000);   // live: tinted changes, order held
// a long list on the server: a table api (C# TableData DevicesTable(TableDataRequest r))
await Sw.Table.Create({ Element: host2, Url: "Api/myapp/DevicesTable" });
```

Small fixed key / value facts (3-6 lines of one item) are not a list of rows: use `Sw.Facts` (ui/README). A hand-made table of rows in page code is a page review finding; `SwWeb check` reports it where its UX rules cover it (SwWeb README "UX guide rules").

### Grid conventions (sort, copy, row actions, links, cards)

- **Sort** (as the original table): a click on a header's sort icon (or Enter on the header) makes that column the primary key and keeps the earlier keys (up to 3, the badge numbers them); a click on the primary column flips its direction; Shift+Enter on a focused header sorts by that column only (a Shift + click only focuses, below). A column sorts ascending first unless the C# `SortedDesc` prop says descending. The table sends no order until the viewer chooses one (the server's own order applies; `TableData.DefaultOrder` is not copied into the request), and the option `Order` (a caller's first order) is the only client side default.
- **Modifier clicks** (UX guide 1.0 INP-2): Shift / Ctrl / Alt / Meta + click anywhere in the table never runs the click's action (no sort, no menu, no row action, no refresh): it moves the keyboard focus to the clicked control (a row action, a tool bar button), else to the grid cell (it becomes the current cell; a header sort icon focuses its header), and shows the ring (`Sw.Focus.Show`; `ModClick`, capture phase on the table root). The table has no row selection, so Ctrl / Shift never select rows. Links keep the browser's gestures (Ctrl + click = new tab), fields their caret, Shift + click extends a text selection. The current cell also shows after a plain click (a thin inset outline, UX guide FOC-3).
- **Selection** (INP-30): cell values are selectable (drag, double click on a word, Shift + click), so are the range, the note and the state texts; the header, row numbers, row actions, tool bar and footer are chrome (not selectable).
- **Copy:** as the original, a plain click (or tap) on a value copies it (the `Sw.Cells` copy on click, `Sw.Clipboard.CopyOnClick`, with its "Click to copy ..." tool tip line; P2-A) and focuses the cell. Copy also with Ctrl+C on the focused cell, or the cell menu (right click, Space, Shift+F10): "Copy value", "Copy raw value", **"Copy link"** (link cells: the link's address, one item per link, "Copy link: <name>" when a cell has several; `Sw.Clipboard.LinkItem`), "Copy row as JSON". **A click with a modifier (Shift, Ctrl, Alt, Meta) on a link** copies its address with a toast, as the original (`Sw.Clipboard.AltClickLinks` on the table root; also in the explore listing; P2-A); the middle button still opens a new tab. "Copy value" / Ctrl+C copy exactly the value (INP-31): a number shown as a plain number without its thousands separators ("1234567"), anything else as shown; the copy toast names the value. The row number and row actions cells have no value to copy (their menu has the actions and "Copy row as JSON").
- **Row actions** (an Actions format column, ex: Kill, End session): always visible on every row, quiet at rest, in a column pinned at the right edge; when the columns fill the frame, rows with three or more actions show a row menu button instead (one or two actions always stay buttons). Every row menu and the cell menu list the safe actions first and destructive ones last after a separator, so the item a menu focuses is not Kill when there is another. A confirmation that closes (Escape or confirmed) gives the keyboard focus back to the row's action, or to the actions cell of the done row (or of the row now in its place). After a final action (End session, Kill, Delete ...) the row stays in place, marked done, through the live refreshes, until a manual refresh or another sort / search / filter / page; a row the server **still lists** after that refresh gets its actions back (the server did not remove it; a failure note goes too, a done note of an action that is not final stays). When the server no longer lists it the range says so with the state of the action's verb ("1 row (ended, shown until you refresh)", "1 row (withdrawn, …)", "1-20 of 20 + 1 deleted row"; `finalState`), never "0 of 0" next to a visible row. **The counts follow at once:** right after a final action succeeded the table re-reads its rows quietly (a live refresh: the row stays in place), so the range text and every count built on it are current without waiting for the next refresh (tables without a refresh were stale until a reload). **Counts for the page** (tab badges, headings): the bubbling `sw-table-count` event on the table root and the option `OnCount(counts, table)`, each time the counts change (a load, a refresh, the re-read after a row action): `{ Count, Shown, First, More, Kept, KeptCount }` (`Count` = the server's row count, a lower bound when `More`; `Kept` = rows of final actions / rows gone under a confirmation are shown until the next refresh, `KeptCount` how many, not in `Count`). **Every kept row is kept:** several rows can be kept at once (`KeepRow` / `KeptOf`, by item), so a row that goes away under its confirmation while other rows of final actions are kept is marked "No longer listed" too, and the range counts each state: "1-16 of 16 + 2 rows (1 ended, 1 no longer listed)", "1-8 of 8 + 2 ended rows". Example: `invTable.E.addEventListener("sw-table-count", ev => tab.SetBadge(ev.detail.More ? "" : String(ev.detail.Count || "")))`. **A row that goes away under its confirmation** (someone else ended / withdrew it, or it expired): while the row action's confirmation is open, a live refresh that no longer lists the row keeps it in its place, muted, "No longer listed" (`RowGone`; the range says "1 row (no longer listed, …)"), so the dialog stays next to the row it is about; the button gets `data-sw-row-gone="true"` and a bubbling `sw-row-gone` event (detail `{ Item, Name, Reason }`: `Reason` is the table's sentence, "OpsVictim is no longer listed: it may have ended, or someone else changed or removed it. Nothing was sent.", for the open confirmation to show); the row is final at once (its actions hidden, "ⓘ No longer listed" in the quiet colour: information, not a success; ✓ only for "done"). A final action that ends "not done" with `false`, 404, 409, 410 or a reason without a status (the row action convention: "409 with the reason"; not 403 / 5xx / aborted / offline) is checked against the list (`GoneCheck`: a quiet re-read with the row kept): when the server no longer lists the row the goal is met and the result is "Withdraw invitation (x): already gone, the server no longer lists it" (polite, the row muted "Already gone …", the counts updated), not an error toast that asks for a reload; when the row is still listed the failure stands ("⚠ … not done" with the server's reason). Cancelling the confirmation of a row that went away shows the list as it is at once. **Busy and result** (FBK-2 / 4 / 5): the busy button is Sw.Cells' (`Sw.Work`: spinner, `aria-busy`, after 2 s an activity list job in the shell); the table adds, after 2 s, the time so far next to the button ("4 s", "1 min 5 s"; the same clock and text as the button's tool tip "Kill: working (4 s)", `Sw.Work.Elapsed`; it sits in the cell's free space, the pinned column keeps its width). While a row action runs its row keeps its place (the order is held, `HoldOrder`), and the action follows its item, not the row element (`ActRow`: rows are reused by position). **The result in exactly one place, and the server's** (one path with `ui/cells.js`): Sw.Cells dispatches `sw-cell-result` on the button (bubbling, before any toast; `detail = { Ok, Value, Error, Text, Name, Work, Url, Ms, Aborted, InPlace, Status, Reason, Note, Neutral }`; `Ok` is false for a thrown request and for a `false` answer) and passes the same object to the refresh callback. The table also listens on the button itself, so the result is not lost when a live refresh moved the rows and replaced the button while its confirmation was open. While the row is on the screen and the tab is visible the table takes the result (`ActionResult` sets `detail.InPlace = true`): Sw.Cells then shows no toast and ends its activity job quietly, and the table shows it in the row: "✓ Kill: done" (or the server's `Done` text of the outcome, else the done text of the action: the 7th part of its format, C# `TableDataActionsFullAttribute`, ex: "ann@example.com must choose a new password at the next sign in"; Sw.Cells puts it on the button as `data-sw-done`; in the grid such a server sentence is the row's result line, `MarkWhy` "ok": the same band as a failure below, in the success colour with the check mark, wrapping, never cut to "…" in the actions cell (Admin N47); the end note keeps it for screen readers, and its tool tip says "You used Disable on this row at 13:16:27." (only a final action's tool tip adds that the server may still list the row)), or **the whole failure sentence with the server's reason as visible text in the row** (`MarkWhy`, UX guide FBK-1 / FBK-5: "⚠ Kill: not done. Process #65596 has already ended.", Sw.Cells' `Note` when it gives one, never only a tool tip): in the grid a band in the room the row gets below its values (the row grows by its height, `--sw-table-whyh`; drawn at the visible left edge of the scrolled area, left of the row actions, so it covers no value and no button, and stays in view when the grid scrolls sideways; the row's note keeps the sentence for screen readers), in the cards a line under the card title (wraps, never cut). The verdict comes from the server's outcome kind, never from the status code (`sw-cell-result` detail `Outcome`, the server's `X-Sw-Outcome` through `Sw.Net.OutcomeKind`): `AlreadyDone` (the goal is met already) shows "ⓘ Kill: not needed. Process #4711 has already ended." and `Gone` "ⓘ Withdraw invitation: no longer there. <reason>", quiet, not red, announced politely; the row is then final like after a done final action (Kill, End session, Withdraw …: its actions and its card menu are not offered again, it stays in its place, muted, until the user's refresh and is counted in the range text "+ 1 ended row"); the same sentence is the note, the tool tip ("… (13:40)") and the announcement (one verdict). Every other refusal (`Refused`, `Denied`, `Invalid`, or no kind) is "⚠ Kill: not done. <reason>": the actions stay, to try again; the line goes with the next try or a refresh by the user (a final action's 404 / 409 / 410 without a kind is checked against the list: when the server no longer lists the row, "already gone"). Announced: "Kill OpsVictim (65596): not done. <reason>" (named like the confirmation, Sw.Cells' `Work`; one sentence per part), a failure assertively, a neutral one politely. Off screen, in a hidden tab or on a page without the table the result is Sw.Cells' toast / activity item. An older Sw.Cells without the event: success = no new error toast (as before). **Focus** (FOC-1): the keyboard place belongs to the action when its button (or the grid) had the focus at the click, and it comes back to the row after **every** outcome (done, not done, already gone, stopped), also when the confirmation closed while the button was busy (disabled: its cell takes the focus, never the page body). A focused row action keeps the keyboard place: when its buttons go away (a final action) the focus moves to the row's actions cell (the done note is read there), and when a focused element of the grid is removed or hidden by a refresh the cell at the same row / column gets the focus (`KeepFocusPlace`, `RestoreFocusPlace`, `NoteFocus`), never the page body; focus the user moved away is not taken back. **The focus follows the item, never the row element** (rows are reused by position): after the confirmation closes, the focus goes to the action's row as it is now (`ItemRow`), its button, else (a hidden button) its actions cell with its note (`FocusActedRow`); when a re-read moves the rows while the focus sits in the row element the action put it in, the focus moves to the action's row, so it never lands on another row's "Kill: done" after a failed Kill. **Your own row** (`MarkCurrent`): a bool column named `IsCurrent` (ex: Active sessions: your own session; it may be a hidden column) gives its row `tr.sw-table-current`, a "You" badge before the row's name (`td[data-sw-you]`, generated content) and the row name "debug (you)" in confirmations and results; the clicked row action gets `data-sw-row-current="true"` (Sw.Cells can warn that the action applies to the viewer). Tables without the column are unchanged.
- **Live refresh on hold** (FBK-7: rows never move under the pointer or the focus): while a mouse / pen pointer is over the rows, a finger touches them, the user put the focus in the grid (a click or a key in it; not the initial focus of `table.html`), a row action waits for its confirmation or runs, or a menu / dialog is open, a live refresh keeps the shown order (`HoldRows`): every shown item keeps its place with its new values (changed values are tinted as usual), an item that left the page keeps its place with its last values (muted), new items wait. Rows whose place differs in the new order get a 3 px accent bar at the row start (the light row tint only on the row under the pointer or with the focus, so a table where most rows move does not read as an error state) and an arrow (↑ / ↓ / ↕ "leaves this page"; `tr[data-sw-move]`, `td.sw-table-movecell` with an `aria-description`; in the cards after the title) and the footer shows "↕ Order on hold" (its tool tip explains it and counts the waiting rows). The new order is shown as soon as the pointer / focus leaves the rows (`ReleaseHold`), at the next refresh after a pop-up closed, or at once with Refresh, a sort, search, filter or page. Items are told apart by the key columns (`ItemText`), else by all values; without unique items the rows refresh as before. The range text is a polite live region that is only set when it changes, so a refresh with the same count says nothing.
- **Row numbers for screen readers** (LST-5): `aria-rowindex` on the header row (1), the shown filter rows and the data rows (their place in the whole result: the first row of page 3 of 25 is 52 + the filter rows); `aria-rowcount` = all rows when the server counted them, -1 while more rows follow (`RowCount` is then only a minimum).
- **Search** (LST-7): every typed word must match (AND; in-memory tables `TableDataTools.Get` / `GetTyped` and the plain database search of `DbSimpleStack` since 2026-10-20; a MySQL full text index keeps its own boolean mode syntax), live after a 300 ms pause, the previous rows stay until the new ones arrive (no empty state flash), the × button clears the search, the range updates once.
- **Live dot** (the page header's "Live: refreshes every 5 s"): while a data request runs the dot grows (1.75 times, quickly; class `sw-table-live-busy`, `LiveDot()`), at least 150 ms so a fast answer is seen too; when the last request ends it shrinks back over 0.25 s. So the dot shows when the table asks the service and when the values are refreshed. Fixed durations (not the theme's motion scale, which would make it invisible in the Pro theme); no animation with reduced motion (the size still changes).
- **Lost connection** (FBK-9): while `Sw.Net.Online` is false a table that has rows keeps them, shows no error toast and a chip "Not updated since 12:40", and pauses its refresh (no request per tick); it fetches once on the `net.online` event (also from the error state; a request still in flight then gets one more right after it only when it fails, so the chip goes with the first good refresh; when it succeeds it is that fetch: often it is the request that told Sw.Net the server is back, and the second identical request 8 ms later is gone, S5b-Ops-1). The table page header says "Paused: not connected (refreshes when the connection is back)" with a hollow dot instead of "Live: refreshes every 5 s" meanwhile. On a narrow footer (phones) the chip is short ("Offline 12:40", never cut) and takes the room of the "Changed" legend and the Rows choice (the pager does not move). A network error before the connection state is known (the probe) is treated as offline too: no "Failed to fetch" toast.
- **Links:** no underline at rest (the data colour); the accent underline shows on hover / focus and in the focused cell; touch screens keep a faint underline.
- **Text ends:** a value cut by a text cap ends with one "…" (the value's own end dots are dropped, never "...."); the tool tip has the whole value. A dot filler (". . . . ." of a fixed width console column, ex: an empty log Prefix) is shown blank.
- **Cards** (phones): a card opens with its title (option `CardTitle`, else a name like column, a text key, a message column (Text, Message ...), else the first text column that is not a key or an id), without a "#n" band; the row number shows only on cards without a title value.

## Not allowed (403)

- `Sw.Table` (table.js): a refused data request (403, `Sw.Access.IsDenied`) shows the shared "not allowed" state of core (`Sw.Page.ShowNotAllowed` in `div.sw-table-denied`: who is signed in, the role needed from the api info, a Home link) instead of "Could not load the data: 403 - Forbidden" + "Try again"; the tool bars (Refresh, Download, search, card bar) are hidden (`.sw-table-denied-on`), refreshing stops (`IsDenied`, `ShowDenied`) and `access.denied` is emitted (guarded actions of the page get disabled).
- api.html (api.js): "Send API call" is always enabled, like the original page (no role lookup before the call); a refused call names the role in the error.
- logo.html / icons.html: a refused request shows the "not allowed" state instead of a toast on an empty page.
